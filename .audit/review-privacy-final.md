Independent privacy and reporting review on 2026-10-19.

Two high severity defects remain in the uncertain-submission contract.

1. The Anthropic SDK retries batch creation internally. `src/bba/llm_client/transport.py:556` constructs `anthropic.Anthropic` without disabling its default retries. The installed SDK and the constructed client both report `max_retries == 2`. The manifest guard around `create` at line 448 cannot observe intermediate accepted requests whose responses are lost. An executed offline probe supplied `httpx.MockTransport`, recorded acceptance of each POST, and raised `httpx.ReadError` after each acceptance. One `submit_batch_only` call issued three POSTs to `/v1/messages/batches` before raising `AnthropicAPIError`. This can produce duplicate paid batches and leave all three remote IDs unknown. Disable SDK retries for non-idempotent creation, or use a provider-supported idempotency contract that demonstrably deduplicates creation. Add a regression using the real installed SDK with a mock HTTP transport. The existing fake SDK boundary misses this behavior.

2. The CLI treats a lost or malformed response as a safely retryable failure. `_envelope_from_cli` at `scripts/pilot/_claude_cli_transport.py:128` maps malformed JSON and missing structured output to the same error envelope as known failures. `_run_one` retries that envelope at line 345 and removes its inflight marker at line 367. An executed offline probe used a runner that recorded remote acceptance and returned `CliOutcome(stdout='{', stderr='', returncode=0)`. With one retry enabled, two fetch calls produced four executions and left no inflight marker. A successful remote execution with truncated stdout is therefore silently repeated both immediately and on resume. Preserve uncertainty for malformed or incomplete responses and for any exit whose pre-submission failure is unproven. Do not retry those outcomes automatically. Distinguish provably safe failures explicitly and test both cases.
