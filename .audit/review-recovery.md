Independent recovery review found two high priority defects in the imported root worktree. Both were reproduced with synthetic contexts and cassette transports. No provider, network, or patient data was used. Application source was not edited.

1. [HIGH] RBC recovery fails when the global missing platelet defer policy is enabled. `src/bba/audit_pipeline/pipeline.py:309` supplies `False` to RBC batch execution, so its manifest and cached call hashes carry `False`. `src/bba/audit_pipeline/resume.py:227`, `:264`, and `:306` instead use the global policy flag. A synthetic RBC run with `enable_missing_platelet_defer=True` interrupted at the first result fetch could not recover when rerun with identical arguments. The retry raised `ResumeReconciliationError` with `batch recovery has unresolved audit rows`. The store contained zero rows and the batch remained `partial`. Fix the effective policy once for each batch and use that same value for manifest validation, call hashing, fetched replay, and cached replay. Add both fetch-crash and call-write-crash regressions for RBC runs with the platelet policy enabled.

2. [HIGH] Deterministic reruns silently accept changed policy. `src/bba/audit_pipeline/manifest.py:53` accepts contexts but no pipeline policy. Its run identity therefore omits `AuditPipelineConfig.enable_missing_platelet_defer`. A missing-count platelet order first run with defer disabled committed `INSUFFICIENT_EVIDENCE`. Rerunning the same run and version with defer enabled and the platelet LLM flag enabled succeeded and reported the audit ID persisted while retaining that old verdict. The evidence was a synthetic injection fixture, so the new policy should route it to `NEEDS_REVIEW` with `injection_detected`. This uses no transport calls. Reject the changed run policy before any writes, including runs that never created an LLM manifest. Add a regression that changes the config flag on a previously deterministic run.
