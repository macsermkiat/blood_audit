---
title: De-identification
description: The local redactor, signed privacy admission, and handling of clinical exports.
---

`bba.deid_redactor` transforms local clinical notes before they can enter a model request. The application accepts only redacted evidence approved by a trusted issuer. Replacing identifiers or computing a hash does not authorize submission.

## Redaction contract

`redact_bundle` takes a `RedactionRequest`, a `RedactorBackend`, and a `KAnonymityGate`. The wrapper preserves clinical roles with tokens such as `[PATIENT]`, `[ATTENDING]`, and `[NURSE]`. It shifts supported date spans to days relative to admission, caps structured age at 89, and checks for semantic degradation.

The k-anonymity check requires a group size of at least five for the quasi-identifier tuple of ward, ICD-3char, age band, sex, and admission month. Failed privacy checks or degraded notes require local review.

The deployment supplies the approved backend and model artifact. The repository does not provide a ready-to-use, clinically approved redaction service. A pass-through backend is suitable only for synthetic tests.

## Signed admission

The trusted local service constructs `RedactionAuthority` with its approved backend, model artifact, privacy gate, and private Ed25519 signing key. `RedactionAuthority.prepare` exports a `PrivacyArtifact` containing the exact redacted evidence and its attestation.

The application receives the artifact and the issuer's public verification key. It must not receive the private signing key. `PrivacyAdmissionPolicy.verify` checks the signature and binds approval to:

- The exact prompt content and task mode.
- The audit ID and run ID.
- The approved redactor version, nonzero model SHA-256, and gazetteer version.
- A passed k-anonymity check and semantic checks.

Evidence must match the redacted notes exactly, in order, with unique evidence IDs. The authority rejects unapproved few-shot examples. The prompt and privacy checks can also require local review.

Set `BBA_PRIVACY_POLICY` to the trust-policy JSON and `BBA_PRIVACY_ARTIFACTS` to the artifact map keyed by audit ID. See [Environment variables](/blood_audit/en/operators/env-vars/) for application configuration.

Without trusted admission, a model-bound row becomes local `NEEDS_REVIEW` with `privacy_admission_failed`. The application does not submit its raw notes. Completed rows remain immutable. To reevaluate a rejected row after approval, use a new approved policy version and run identity.

## Exception logs

The CLI explicitly calls `bba.cli.phi_scrubber.install_excepthook` before dispatch. Importing `bba.deid_redactor` does not install a process-wide hook.

The hook records the exception type and code locations. It withholds exception messages and local values, which can contain arbitrary clinical text or credentials. It renders opaque type and length markers for local bindings. This protection does not make arbitrary application logging safe. Keep raw bundles and credentials out of log events.

## Development fixtures

Use fully synthetic notes and identifiers in tests and cassettes. `bba.deid_redactor.PHI_REGEXES` is the shared pattern set for PHI-shaped fixture checks. Reuse it rather than copying expressions.

Clinical exports remain sensitive after identifiers are replaced. A bundle derived partly from real data, including an encrypted or "mock-AN" bundle, is not an approved synthetic fixture. Keep raw exports, clinical free text, and encrypted clinical bundles out of Git. A changed admission number alone says nothing about identifying details left in a note.

## Source files

- `src/bba/deid_redactor/redactor.py` implements the wrapper.
- `src/bba/deid_redactor/admission.py` defines issuer and verifier contracts.
- `src/bba/application/audit.py` configures admission at the application boundary.
- `src/bba/cli/phi_scrubber.py` implements exception-log handling.
