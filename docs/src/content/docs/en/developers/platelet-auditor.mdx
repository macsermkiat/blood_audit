Platelet orders use a separate value lookup and deterministic classifier. Their audit rows carry `component="platelet"`. Reporting and review keep component identity so platelet findings do not enter RBC-only statistics.

## Intake and count lookup

The HOSxP order builder admits orders containing an RBC product as `red_cell`, or orders made entirely of platelet products as `platelet`. Unsupported and mixed non-RBC products are excluded. `bba.component_map` exposes a separate six-family name classifier, but it is not the order builder's runtime gate.

`bba.platelet_lookup` reads hematology `LABEXM = "290078"` in ×10³/µL. There is no POCT fallback. `parse_platelet_count` handles comma-grouped values and censored bounds such as `<2`. Missing, nonnumeric, nonfinite, or out-of-range values return `None`. `PlateletObservation` preserves an aware UTC time and lab `item_no` for ties.

MTP-window platelet co-orders are suppressed upstream as independent audit units. They contribute to the MTP signal without creating another audit row.

## Deterministic gate

`classify_platelet` applies these rules in order:

| Condition | Classification | Reason |
| --- | --- | --- |
| Missing count, missing-count defer option off. | `INSUFFICIENT_EVIDENCE` | `plt_missing` |
| Missing count, missing-count defer option on. | `NEEDS_REVIEW` | `plt_missing_defer_llm` |
| Count ≥ 100 ×10³/µL. | `POTENTIALLY_INAPPROPRIATE` | `plt_ge_100` |
| Count ≤ 10 ×10³/µL, fresh, with a qualifying indication, no exclusion code, and prophylaxis auto-clear enabled. | `APPROPRIATE` | `plt_lt_10_heme_prophylaxis` |
| Other present count. | `NEEDS_REVIEW` | `plt_defer_llm` |

The prophylaxis boundary includes exactly 10. The historical reason name `plt_lt_10_heme_prophylaxis` does not change that comparison. Freshness must be `fresh`, meaning less than 24 hours old.

Qualifying diagnosis prefixes are `C8`, `C9`, `D61.1`, `Z51.1`, `Z94.8`, and `T86.0`. `D46` additionally requires `Z51.1` or recent chemotherapy-medication evidence. The library pipeline does not pass medication events into this gate, so its D46 route requires `Z51.1`.

Exclusion prefixes cover ITP, TTP/TMA, HUS, HIT, specified aplastic-anemia categories, dengue, and snake venom. The exact normalized lists live in `src/bba/platelet_classifier/classifier.py`. An exclusion prevents this structured prophylaxis clear and routes the case onward. A low count alone does not qualify.

`PLATELET_PROPHYLAXIS_AUTOCLEAR_ENABLED` defaults to true in the pipeline. The classifier remains pure and receives its enablement through `PlateletClassifierInputs`. Turning that option off removes this single auto-clear route. The deterministic gate never emits `INAPPROPRIATE`.

## Model route and completion

`PLATELET_LLM_ENABLED` defaults to false. Deterministic-final platelet rows persist without that route. Unresolved platelet rows need the model route enabled and trusted privacy admission before submission.

With the route disabled, those unresolved rows remain uncommitted. `audit_bundle` detects the orphan IDs and fails without an application completion marker. Do not interpret a successful ingest or persisted RBC rows as a completed mixed-component audit.

When enabled, the pipeline submits platelet work in separate batches after RBC work. Missing admission produces local privacy review rather than exposing raw notes. Committed unresolved platelet results appear in the reviewer queue alongside unresolved RBC results.

## Response guardrails

The platelet response declares grounded hard signals for active bleeding, procedure indication, marrow-failure prophylaxis, intracranial bleeding, and aplastic anemia on active therapy. `platelet_overclear_suspect` changes an unsupported model `APPROPRIATE` to `NEEDS_REVIEW` with `platelet_llm_overclear_suspect`.

The prompt's indication boundaries use inclusive ≤10, ≤20, ≤50, and ≤80 ×10³/µL where specified. The high-target surgical or intracranial exception retains a strict `count < 100` boundary. These indication-specific rules do not create blanket deterministic clears.

Two additional guardrails default to off:

- `PLATELET_TREND_GUARDRAIL_ENABLED` requires a supported projection to ≤10 within 24 hours when that expected decline is the only positive signal. `project_24h` computes the projection from the last two pre-order counts.
- `PLATELET_SPECIALIST_TARGET_GUARDRAIL_ENABLED` can route `INAPPROPRIATE` to review for a qualifying documented specialist target. The target is not itself a positive policy indication.

The shared `label_reasoning_conflict` guardrail also routes contradictory labels and reasoning to review. Quote verification still applies. These checks constrain model output, but do not establish clinical validity.

The relevant packages are `src/bba/platelet_classifier/`, `src/bba/platelet_guardrail/`, and `src/bba/audit_pipeline/replay.py`. The prompt wording is in `src/bba/prompt_builder/`.
