Run the blocking source checks from the repository root:

```bash
uv sync --frozen --extra live
uv run ruff check .
uv run ruff format --check .
uv run mypy src
BBA_REQUIRE_POSTGRES_TESTS=1 uv run --extra live pytest -q --tb=short --cov=src/bba --cov-fail-under=80 --cov-report=term-missing
```

The `live` extra installs the provider SDK so transport tests can import it. Tests still reject live provider calls. Start Docker before the required Postgres run.

## Required Postgres tests

`tests/conftest.py` provides the shared Postgres 16 container fixture. With `BBA_REQUIRE_POSTGRES_TESTS=1`, missing dependencies or an unavailable Docker daemon fail the test run. CI sets this variable and enforces at least 80 percent source coverage.

Without that variable, the shared fixture may skip when dependencies or Docker are unavailable. Container startup, migration, test-body, and teardown errors propagate after the availability checks. Do not catch those errors broadly and convert them into skips.

Report skipped or deselected tests with their reasons. A run without database tests does not establish that database integration passes. Tests that require a local clinical workbook also need that separate input. Do not copy patient data into the repository to satisfy a fixture.

## Offline model tests

`bba.audit_pipeline.cost_guard` blocks live transport in test contexts. Use synthetic fixtures and cassette-backed responses. `tests/unit/test_llm_client.py` and `tests/unit/test_application_cassette.py` construct their cassette fixtures in temporary directories. A cassette recorded from clinical data remains sensitive even if its filename looks synthetic.

`tests/unit/test_application.py` checks local audit composition. `tests/unit/test_application_cassette.py` exercises admitted cassette requests. Production Postgres composition has its own integration tests. These establish application behavior on synthetic inputs, not clinical validity or hospital deployment readiness.

Grounding tests must exercise the real checks for source identity, normalized text, quote boundaries, uniqueness, and lab tuples. Recovery tests must prove that stale context and changed requests are rejected, and that repeated replay does not duplicate committed results.

## Type checks and CI

`pyproject.toml` sets strict mypy behavior for source code. `uv run mypy src` blocks CI. `uv run mypy tests` is advisory while test-helper typing debt remains. Advisory errors still deserve inspection because they can hide mistakes in fixtures or assertions.

`.github/workflows/ci.yml` runs lint and format checks, source typing, and pytest with Docker. The `ci` job aggregates those required results. Test totals change with the code and available fixtures, so use the current run output instead of a fixed expected pass count.
