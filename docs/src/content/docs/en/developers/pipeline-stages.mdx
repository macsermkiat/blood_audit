## Prepare local evidence

1. Seal the canonical CSV bundle in a private source snapshot. Verify its input hash, schema, code version, and configuration before classification.
2. Validate and normalize the export with `bba.ingest`.
3. Select eligible orders with `bba.audit_orders`. The exporter must supply the adult cohort because the canonical export has no age column.
4. Use the component-specific lab lookup, vitals extractor, and cohort detector to assemble pre-order clinical context. Issue time remains an evidence anchor, not proof that a transfusion occurred.
5. Attach returns-ledger disposition, declared use, and MSBOS reservation context where available.

## Apply deterministic rules

The pipeline calls the RBC or platelet classifier on each active context. It persists deterministic-final results without sending a model request. MTP-suppressed platelet co-orders intentionally emit no independent audit row.

RBC `NEEDS_REVIEW` and `POTENTIALLY_INAPPROPRIATE` results proceed to the model admission boundary. Platelet review routing also requires `PLATELET_LLM_ENABLED`. See [Hb rules](/blood_audit/en/developers/three-tier-hb/) and [Platelet auditor](/blood_audit/en/developers/platelet-auditor/).

## Admit and submit a model request

`bba.evidence_bundle_builder` assembles local evidence. An approved local issuer redacts it and signs approval for the exact prompt, audit ID, and run ID. The application verifies that approval using the issuer's public Ed25519 key. See [De-identification](/blood_audit/en/developers/deid/).

The prompt builder formats the approved evidence. Before submission, immutable manifests record the request content and the context required for recovery. Admitted model runs use Postgres checkpoints. The live transport disables automatic SDK retries. An uncertain remote outcome requires reconciliation rather than another automatic submission.

In local mode, or when privacy admission fails, model-bound RBC rows commit as `NEEDS_REVIEW` with `privacy_admission_failed`. Raw notes do not enter transport or persisted model calls.

## Verify and commit

The response path validates structured output, verifies citations against the redacted evidence, and applies component-specific guardrails. It preserves ordered attempts and selects the latest attempt that passes verification. If none passes, the row becomes `NEEDS_REVIEW` with `hallucination_suspect`.

`bba.audit_store` writes calls before the result row and writes the commit marker last. Read APIs expose committed results. The application records CLI completion only when eligible, nonsuppressed work is committed. Ingested rows do not count as audited results.

## Recover an interrupted batch

The batch store tracks `pending`, `submitted`, `partial`, `complete`, and `failed` states. `resume_on_startup` checks the recorded code version and matching context, policy, and request identity before reconstructing results.

A submitted or partial batch can recover from persisted calls or poll its recorded remote batch ID. Cached responses pass through the real verifier again. Missing or changed manifests block recovery. A pending batch with uncertain submission status requires operator reconciliation and is marked failed. Recovery does not guarantee that every interrupted run can finish without intervention.

See [Audit store](/blood_audit/en/developers/audit-store/) for committed identity and [Audit command](/blood_audit/en/operators/audit-command/) for CLI usage.
