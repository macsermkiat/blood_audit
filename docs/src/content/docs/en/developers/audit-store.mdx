---
title: Audit store
description: Immutable result rows, ordered model calls, and recoverable commit ordering.
---

`bba.audit_store` persists `AuditRow` results and `LlmCall` records in Parquet. A row represents one audited component order. Model-call records preserve individual attempts and their provenance. Deterministic and privacy-rejected rows use explicit marker-call provenance rather than claiming a model or redactor ran.

Both models are frozen Pydantic records. Nested JSON values are deeply frozen. The model boundary rejects naive datetimes and normalizes aware datetimes to UTC. Identifiers use `SafeId`, which rejects empty values, path separators, `.` and `..`.

## Classification fields

`rule_classification` records the deterministic result. `final_classification` records the result after model verification and guardrails, when those steps apply. Both use the stored classification vocabulary:

```python
Classification = Literal[
    "APPROPRIATE",
    "INAPPROPRIATE",
    "NEEDS_REVIEW",
    "INSUFFICIENT_EVIDENCE",
    "POTENTIALLY_INAPPROPRIATE",
    "PREOP_RESERVATION_UNCONFIRMED",
    "PREOP_OVER_RESERVATION",
    "RETURNED_NOT_TRANSFUSED",
    "PERIOP_TRANSFUSION_EXEMPT",
]
```

`RETURNED_NOT_TRANSFUSED` and `PERIOP_TRANSFUSION_EXEMPT` are excluded from appropriateness scoring. Reservation findings remain separate from transfusion-indication judgments.

`LLM_REVIEW` is an internal routing concept. `hallucination_suspect` and `privacy_admission_failed` are review reasons. None is a stored classification literal.

## Commit ordering and idempotency

A write persists its call records first, then the result row, and finally the commit marker. Result reads require a valid commit marker. An interrupted write can therefore leave a call without publishing a partial result.

A committed `(audit_id, run_id, code_version)` makes a repeated write a no-op. Read APIs accept a code-version filter so a result cannot accidentally join calls from another version. Individual calls preserve `attempt_index`, model identity, and request provenance. Recovery uses the same ordered attempts and verification rules as normal execution.

The CLI writes real `AuditRow` results through this store. Its separate completion marker records successful application completion. `--force` bypasses that CLI shortcut and logs the override. It does not replace immutable results. Changed analysis requires a new policy or configuration identity.

## Recovery manifests

Run-context manifests bind clinical context, feature flags, and policy configuration. Batch manifests additionally bind ordered audit IDs, exact requests, and model settings. Transport manifests bind provider payloads and the remote batch ID.

Cached results are reusable only when the exact request identity matches. A batch ID or a prompt hash alone is insufficient. Recovery rejects evidence, model, policy, or code-version drift and reruns grounding before publishing a reconstructed result. If remote submission may have happened without a durable binding, reconcile that outcome before resubmission.

## Storage and Postgres

Audit rows, calls, and manifests use owner-only directories and files. Existing files with unsafe permissions or final symlinks are rejected. Sealed source snapshots use read-only permissions. Treat all these artifacts as clinical records.

Postgres holds `batch_runs` checkpoints and `review_actions` adjudication history. These stores have separate migration and role requirements. Set `BBA_DB_URL` to a runtime DSN such as `postgresql://user@host/database`. The SQLAlchemy review adapter converts that DSN through `ReviewActionsConfig.sqlalchemy_dsn`. Do not pass a `postgresql+psycopg://` SQLAlchemy URL to a direct psycopg connection.

## Retention

`migrate_cold_storage` supports moving older extended-thinking payloads to cold storage. The documented retention interval is 90 days. Migration is an explicit operation, not an automatic property of a stored row.

The current model and storage contracts are in `src/bba/audit_store/models.py` and `src/bba/audit_store/store.py`. Recovery checks live in `src/bba/audit_pipeline/manifest.py` and `src/bba/audit_pipeline/resume.py`.
