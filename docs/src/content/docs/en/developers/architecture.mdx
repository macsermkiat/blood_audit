`bba audit` validates a canonical HOSxP export and writes audit results. `bba.application` connects the CLI to context assembly, privacy admission, and `bba.audit_pipeline.run_pipeline`. The pipeline applies deterministic rules before considering a model request.

## Application boundaries

| Package | Responsibility |
| --- | --- |
| `bba.cli` | Parses commands and configuration, manages CLI run markers, and installs exception-log handling. |
| `bba.application` | Seals source snapshots, assembles canonical clinical context, configures transport and admission, and composes reporting, evaluation, monitoring, and review. |
| `bba.ingest` | Validates and normalizes the canonical CSV bundle. |
| `bba.audit_orders` | Selects eligible order-level audit units and separates RBC from platelet orders. |
| `bba.hb_lookup`, `bba.platelet_lookup` | Select pre-order lab results and trends. |
| `bba.vitals_extractor`, `bba.cohort_detector` | Extract structured clinical context. |
| `bba.deterministic_classifier`, `bba.platelet_classifier` | Apply component-specific deterministic rules. |
| `bba.returns_ledger`, `bba.declared_use`, `bba.preop_reservation` | Interpret unit disposition, declared use, and MSBOS reservations. |
| `bba.evidence_bundle_builder`, `bba.deid_redactor`, `bba.prompt_builder` | Assemble evidence and require approved redaction before model submission. |
| `bba.llm_client`, `bba.quote_grounder`, `bba.platelet_guardrail` | Transport model requests, check citations, and apply response guardrails. |
| `bba.audit_pipeline` | Classify, partition, submit, verify, persist, and reconcile interrupted batches. |
| `bba.audit_store` | Persist immutable audit rows, ordered calls, and commit markers. |
| `bba.dashboard`, `bba.review_actions` | Authenticate review requests and record adjudication with revision checks. |
| `bba.report_generator`, `bba.attribution` | Produce reports with physician attribution and per-row provenance. |
| `bba.eval_harness`, `bba.monitoring` | Compare reviewed labels and committed re-audits. |

`bba.component_map` also exposes a six-family name classifier. The supported HOSxP order builder uses product-code allow-lists for its RBC and platelet intake. Do not assume every caller uses the name classifier.

## Data and recovery identity

The application seals input CSV bytes before context assembly. It verifies the snapshot against the source identity, schema, code version, and application configuration. Exporter changes cannot replace the in-progress snapshot.

Deterministic-final rows write without a model call. Other RBC rows require signed privacy admission. Without it, the application commits local review results. The platelet model route has its own feature flag. If the flag leaves eligible platelet work uncommitted, the application fails without a completion marker.

For admitted model work, immutable manifests bind ordered audit IDs, evidence, prompt content, model settings, and policy context. Recovery rejects changed identity and reruns the real verifier before rebuilding rows. An uncertain submission requires operator reconciliation before another submission.

A completed `(audit_id, run_id, code_version)` is immutable. `--force` bypasses the CLI completion shortcut and records the override. It does not overwrite committed rows or manifests. See [Audit store](/blood_audit/en/developers/audit-store/).

## Deployment dependencies

Local deterministic audits need neither model credentials nor Postgres. Admitted cassette and live model runs use a migrated Postgres batch store. The dashboard also needs a migrated review store, a trusted identity adapter, and an HTTPS reverse proxy.

The application does not bundle the hospital's approved redaction backend or identity service. See [Application integration](/blood_audit/en/operators/integration-seams/) for those operator-supplied dependencies and [Pipeline stages](/blood_audit/en/developers/pipeline-stages/) for the processing sequence.
