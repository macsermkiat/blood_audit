---
title: audit command
description: Inputs, configuration, persistence, and recovery behavior of bba audit.
---

`bba audit` validates a canonical HOSxP bundle, assembles orders, and commits audit classifications. It reads exports and writes local audit artifacts. It does not update HOSxP.

```sh
uv run bba audit --input /srv/bba/export/BDVST.csv
uv run bba audit --run-id RUN_ID
```

## Arguments

| Option | Contract |
| --- | --- |
| `--input PATH` | Path to `BDVST.csv` beside the other canonical CSVs. Computes a run identity from the bundle, schema, code version, and explicit application configuration. |
| `--run-id ID` | Selects a recorded run. Resumes incomplete work from its recorded source snapshot when configuration still matches. A completed run is a no-op unless forced. |
| `--force` | Bypasses the completed-run shortcut and appends an `audit_log` entry with `idempotency_override=true`. Committed results and request manifests remain immutable. |

Exactly one of `--input` and `--run-id` is required. Runs sharing a run ID take the same run lock. Different run IDs can run concurrently.

## Configuration and results

`BBA_DATA_DIR` is required. Without `BBA_APPLICATION_CONFIG`, the application uses local mode with the `repository-policy` policy version. Deterministic decisions commit to the audit store. Cases that require model evidence commit as `NEEDS_REVIEW` with `privacy_admission_failed` without making a model call.

An explicit application JSON file contributes its canonical JSON to the run identity. It selects `local`, `cassette`, or `live` transport and the policy version. Model submissions require signed evidence admission and durable Postgres checkpoints. See [Environment variables](/blood_audit/en/operators/env-vars/).

A completion marker is written only after committed `AuditRow` IDs are recorded. Ingested tables do not count as audit results. An empty eligible cohort fails. A platelet order suppressed within an MTP window intentionally emits no audit row.

## Run identity and retained evidence

The bundle's canonical CSV content, schema fingerprint, and package version determine the base identity. An explicit application configuration also contributes to the audit identity. Changing a secondary canonical CSV can therefore produce a different run ID.

The application copies the canonical bytes into a sealed source snapshot before classification. Snapshot files and the manifest use mode 0400 inside an owner-only directory with mode 0500. The application verifies the input identity, schema, configuration, and code version before using the snapshot. Exporter edits do not change the running audit.

Clinical rows, calls, request manifests, and ordinary analysis artifacts use owner-only files and directories. Existing storage with broader permissions or final symlinks is rejected. Keep `identity.key`, source bindings, snapshots, and committed records together under the approved backup and retention policy.

## Resume interrupted work

Use `--run-id` with the recorded ID and matching application configuration. The sealed snapshot allows recovery even after the original exporter files are removed.

Known submitted batches can recover using their stored identity and ordered calls. An uncertain remote submission requires operator reconciliation. The command does not silently resubmit an uncertain request. Preserve the checkpoint records and determine the provider outcome before continuing.

## Evaluate changed policy or evidence

Use a new approved `policy_version` in `BBA_APPLICATION_CONFIG` for changed analysis. Prepare signed evidence for that new run identity. Keep cassette contents fixed for a configured run.

Obtaining a privacy artifact after a local run completes does not change its committed result. `--force` does not authorize replacing a classification, a request manifest, or a completed admission decision.

## Platelet route limit

`PLATELET_LLM_ENABLED` is false in the repository configuration. If a bundle contains platelet orders that require the disabled review route, the application rejects the uncommitted work and does not mark the run complete. A local audit is not a guarantee that every platelet order can complete. Confirm the approved deployment route before selecting a platelet cohort.
