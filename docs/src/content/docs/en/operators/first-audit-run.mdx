---
title: First audit run
description: Commit a local audit without model credentials or a Postgres connection.
---

This run writes deterministic classifications and flags cases that need model evidence for human review. Use a synthetic export while checking installation, or an approved hospital export on its authorized host.

## Prepare a complete bundle

Place all [13 canonical CSVs](/blood_audit/en/operators/ingest-csv/#expected-tables) beside `BDVST.csv`. Apply the approved adult cohort filter during export. Keep the bundle outside the repository.

Choose a private persistent data directory. The application rejects existing clinical storage with broader permissions, so review ownership and access before reusing older directories.

```sh
export BBA_DATA_DIR=/srv/bba/data
```

These examples use `/srv/bba/export` for the staged bundle. Replace both paths with approved locations on your host. For this first run, use the default local application configuration. An existing `BBA_APPLICATION_CONFIG` can select a different mode.

## Validate the bundle

This optional preflight checks headers and row normalization. It writes an ingest completion marker and does not classify orders.

```sh
uv run bba ingest /srv/bba/export/BDVST.csv
```

A successful command logs `ingest.complete`. Missing required files or columns stop the command. The audit command also validates its sealed input snapshot, so a separate ingest is optional.

## Commit the audit

`PLATELET_LLM_ENABLED` is false in the repository configuration. If a bundle contains platelet orders that require the disabled review route, the application rejects the uncommitted work and does not mark the run complete. A local audit is not a guarantee that every platelet order can complete. Confirm the approved deployment route before selecting a platelet cohort.

```sh
uv run bba audit --input /srv/bba/export/BDVST.csv
```

The command seals a source snapshot, assembles orders, classifies them, and commits `AuditRow` records under `$BBA_DATA_DIR/audit_store`. Its completion state counts committed audit rows. An empty eligible cohort fails without a completion marker.

Record the run ID from the structured logs. A successful audit logs `audit.complete` with its row count. Cases that require model review stay `NEEDS_REVIEW` with `privacy_admission_failed` in local mode. Those cases have not received a model judgment.

The first run creates `identity.key` for stable HMAC patient and admission identifiers. Back up the key with the data directory.

## Check a rerun

Repeat the audit command with the same bundle, configuration, and code version. A completed run logs `audit.noop`. It reuses committed results.

`--force` bypasses the completion shortcut and records an override. It does not replace committed classifications. To evaluate changed policy or newly admitted evidence, create a new policy version and run. See the [audit command reference](/blood_audit/en/operators/audit-command/).

## Render the committed results

The monthly report covers red-cell rows and rejects a platelet-only run. It requires the corresponding order export and doctor registry for attribution.

```sh
export BBA_BDVST_CSV=/srv/bba/export/BDVST.csv
export BBA_DCT_CSV=/srv/bba/export/DCT.csv
uv run bba report --run-id RUN_ID --format html
```

Replace `RUN_ID` with the recorded ID. The command prints the HTML artifact path. Keep the report within the approved review channel. See [Generate the report](/blood_audit/en/operators/generate-report/) for JSON and PDF outputs.
