---
title: Troubleshooting
description: Resolve configuration, admission, recovery, attribution, and review-service failures.
---

Keep error reports free of clinical text, identifiers, tokens, and database credentials. The CLI's exception hook records types and code locations while withholding messages and local values. Use synthetic reproductions when sharing a failure.

## `BBA_DATA_DIR` is missing or invalid

Set an absolute path that the service user can write to. Existing clinical storage must have owner-only access and must not use final symlinks. Review older storage ownership and permissions offline before migration. The application does not silently change access to existing records.

## Postgres rejects the connection URL

Use a plain DSN such as `postgresql://bba@db.internal/blood_audit` for `BBA_DB_URL`. The batch checkpoint store uses psycopg directly. The review adapter converts the DSN for SQLAlchemy internally. A `postgresql+psycopg://` URL is not a shared application DSN.

Check migration state and the selected role's privileges after checking connectivity. Model checkpoints and reviewer actions have their own storage requirements.

## Model cases stay in local review

In default local mode, this is expected. The application commits `NEEDS_REVIEW` with `privacy_admission_failed` for cases that need model evidence.

For a configured model run, verify the application JSON, trust-policy path, approved public key, and signed artifacts. Attestations must match the exact prompt, run ID, audit ID, and approved redactor. See [Model review settings](/blood_audit/en/operators/env-vars/#model-review).

A completed local result remains immutable after you add admission files. Create a new approved policy version and run, then prepare artifacts for that identity.

## An audit rerun is a no-op

### Run-level idempotency

The same canonical bundle, schema, code version, and application configuration select the same audit identity. A completed run logs `audit.noop`.

`--force` bypasses that shortcut and records an override. The pipeline still preserves committed classifications and request manifests. Do not edit completion files to replace results. Use a new policy version for changed analysis.

## A provider submission has an uncertain outcome

Stop automatic resubmission. Preserve request manifests and batch checkpoints, and reconcile the request against provider records. The application does not silently retry uncertain submissions. Once the outcome is known, use the recorded run and configuration for the appropriate recovery path.

## A report cannot resolve attribution

Set `BBA_BDVST_CSV` to the matching export containing `REQNO` and `DCTREQ`. Set `BBA_DCT_CSV` to the doctor registry. Both report and dashboard startup need these inputs. A report also rejects mixed applied policy versions, conflicting redactor versions, and multiple local calendar months.

## The dashboard returns HTTP 401

Verify that the identity adapter issued a valid `bba_session` cookie using the same secret as the dashboard. Confirm the expiry, externally visible HTTPS origin, and cookie attributes. See [Serve authenticated review](/blood_audit/en/operators/integration-seams/#serve-authenticated-review).

A signed session is required even when accessing the service through a proxy. A form field cannot supply reviewer identity.

## A review save returns HTTP 403 or 409

A 403 can indicate an origin or CSRF mismatch. Use the configured HTTPS origin and obtain a fresh session-bound form. A 409 indicates that the decision changed since the form loaded. Reload the case, inspect the current decision, and submit a deliberate update.

## Postgres tests are skipped

Optional local database tests can skip when Docker is unavailable. That does not verify database behavior. Start Docker and run the required database suite with `BBA_REQUIRE_POSTGRES_TESTS=1`, as described in [Testing](/blood_audit/en/developers/testing/). Required-mode infrastructure failures must fail the run.
