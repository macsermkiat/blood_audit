---
title: Ingest CSV
description: Canonical HOSxP input files and the validation-only ingest command.
---

`bba ingest` validates and normalizes a HOSxP CSV bundle. It records a completion marker after the normalization pass. Use `bba audit` to classify orders and commit audit rows.

```sh
export BBA_DATA_DIR=/srv/bba/data
uv run bba ingest /srv/bba/export/BDVST.csv --schema-version v1
```

All canonical files must be in the same directory. Apply the approved adult cohort filter during export because this bundle has no age column.

## Expected tables

| CSV | Purpose |
| --- | --- |
| `BDVST.csv` | Order header, patient and admission identifiers, product, request time, and ordering doctor `DCTREQ`. |
| `BDVSTDT.csv` | Product details and declared use through `USETYPE`. |
| `BDVSTTRANS.csv` | Per-unit disposition ledger for returned, transfused, and incompatible units. |
| `BDTYPE.csv` | Blood-product reference. |
| `BDVSTST.csv` | Transfusion-status reference. |
| `Diagnosis.csv` | Diagnosis codes for cohort and exclusion checks. |
| `Lab.csv` | Hemoglobin, platelet count, and other laboratory evidence. |
| `Med.csv` | Medication evidence. |
| `IPDADMPROGRESS.csv` | Progress-note evidence retained locally until approved redaction and admission. |
| `IPDNRFOCUSDT.csv` | Nursing-note evidence with the same admission requirement. |
| `IPTSUMOPRT.csv` | Operative events and timestamps. |
| `INCPT_OPRTACT.csv` | Procedure charges pre-joined on `Income`. |
| `ICD9CM.csv` | Procedure dictionary and OR classification. |

The schema definitions and normalization rules live in `src/bba/ingest/`. Normalization handles declared case mappings, duplicate header names, and projection to known columns. Extra columns are dropped and recorded. Missing required columns or canonical files fail validation.

`DCT.csv` is an additional attribution input for reports and the dashboard. It is not one of the 13 canonical audit files.

## Ingest output

The command uses `$BBA_DATA_DIR/ingest/v1/` as its output root. A `_run_<run_id>.complete` marker records successful validation and row normalization. The standalone ingest command does not write normalized-table Parquet payloads or classified `AuditRow` records.

An identical bundle, schema, and code version reuses its completed ingest identity. Without a completion marker, a later invocation runs validation again.

The audit command has its own run identity, sealed snapshots, and result persistence. A successful ingest marker is not evidence that orders have been audited. See [First audit run](/blood_audit/en/operators/first-audit-run/).

## Protect the export

Keep exports and derived artifacts outside the repository. Encrypted identifiers do not establish that a bundle is safe to publish. Use synthetic placeholders such as `PHI_xxx_001` in documentation, screenshots, and issue reports.
