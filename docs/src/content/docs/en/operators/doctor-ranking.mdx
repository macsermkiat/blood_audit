title: Doctor and department ranking
description: Rank pilot verdicts with complete denominators and explicit attribution inputs.

Keep ranking inputs and outputs within the approved review channel. They connect physician identities with clinical verdicts. Encrypted patient identifiers do not make these files suitable for public sharing.

## Rank a pilot run

Use `rank_merged.py` for the [research pilot](/blood_audit/en/operators/run-pipeline/#reproduce-a-research-pilot). It combines the deterministic `report.csv` with `llm_report.json` before aggregation.

The pilot's model audit store omits many deterministic terminal decisions. Reading only that store would leave those orders out of the denominator. This limitation concerns the pilot script workflow, rather than the supported application's full audit composition.

Set `BBA_PILOT_WORK_DIR` to the pilot output directory and provide the corresponding `BBA_BDVST_CSV` and `BBA_DCT_CSV` exports. Run each component separately because the trigger statistics use different laboratory values.

```sh
uv run python scripts/pilot/rank_merged.py red_cell
uv run python scripts/pilot/rank_merged.py platelet
```

The model verdict replaces a deterministic verdict only when the deterministic result routed the order for further review. Deterministic terminal decisions remain final for the merge. A model `REQNO` absent from the report fails validation.

Each component writes `<component>_doctor_ranking.csv`, `<component>_department_ranking.csv`, and `<component>_doctor_rankings.html` under `BBA_PILOT_WORK_DIR`.

## Rank reviewed labels or stored pipeline rows

`rank_doctors.py` selects a source through `BBA_VERDICT_SOURCE`. The default `human` source reads the review workbook's Sheet1, column J. The `pipeline` source reads red-cell rows from the selected run in an audit store. Select the latter only when its committed rows cover the population you intend to rank.

```sh
export BBA_REVIEW_XLSX=/srv/bba/reviewed-labels.xlsx
export BBA_BDVST_CSV=/srv/bba/export/BDVST.csv
export BBA_DCT_CSV=/srv/bba/export/DCT.csv
export BBA_PILOT_WORK_DIR=/srv/bba/pilot
export BBA_PILOT_REPORT_CSV=/srv/bba/pilot/report.csv
uv run python scripts/pilot/rank_doctors.py
```

Set paths explicitly to avoid the research defaults that point to local workbooks and adjacent Bloodbank exports. Missing inputs fail the script.

| Variable | Contract |
| --- | --- |
| `BBA_VERDICT_SOURCE` | `human` by default, or `pipeline`. |
| `BBA_REVIEW_XLSX` | Human source workbook. Default is `~/Downloads/Review การใช้เลือด.xlsx`. |
| `BBA_BDVST_CSV` | Order export with `REQNO` and `DCTREQ`. Research default is `../Bloodbank/data/encrypted/BDVST.csv`. |
| `BBA_DCT_CSV` | Doctor registry. Research default is `../Bloodbank/data/raw/DCT.csv`. |
| `BBA_PILOT_WORK_DIR` | Output directory. Default is `/tmp/bba_mini`. |
| `BBA_PILOT_REPORT_CSV` | Per-order trigger statistics. Required for either source. Defaults to `report.csv` in the work directory. |
| `BBA_AUDIT_STORE_DIR` | Pipeline source audit-store root. Falls back to `$BBA_DATA_DIR/audit_store`. |
| `BBA_RUN_ID` | Required single-run scope for the pipeline source. |
| `BBA_CODE_VERSION` | Optional pipeline code-version scope. Use it when the selected run has ambiguous versions. |

The script writes `doctor_ranking.csv`, `department_ranking.csv`, and `doctor_rankings.html` in the work directory. Its reconciliation summary includes verdict counts, the ranked bucket, the minimum sample threshold, and output row counts.

## Interpret the attribution

`bba.attribution` ranks the top 10 doctors and departments using appropriate, inappropriate, and unresolved buckets. `REQNO` links to `BDVST.DCTREQ`, which links to `DCT.csv`. Department means the ordering doctor's department.

The pipeline source counts `RETURNED_NOT_TRANSFUSED` and `PERIOP_TRANSFUSION_EXEMPT` in an excluded bucket. It includes `PREOP_OVER_RESERVATION` on the inappropriate side and also records `over_reservation_count` separately. Check the selected source's population before interpreting rates.

These ranking scripts are separate from `bba report`. The supported report and dashboard use the same attribution loaders. See [Generate the report](/blood_audit/en/operators/generate-report/) for their input contract.
