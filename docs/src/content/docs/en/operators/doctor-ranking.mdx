The attribution feature (`bba.attribution`) ranks the top-10 ordering
doctors and top-10 departments by how appropriate their blood orders
are, split into three buckets: Appropriate, Inappropriate, and Unresolved.

:::caution[Real PHI in inputs and outputs]
The inputs are real encrypted patient/order data and the outputs contain
real PHI: doctor identities tied to real appropriateness verdicts. Never
commit, email, or share the workbook, the `BDVST`/`DCT` CSVs, or the generated
CSV/HTML outputs outside the approved review channel.
:::

## Ranking a pilot run: use rank_merged.py

To rank the output of a pilot run (Path A in
[Run the pipeline](/blood_audit/en/operators/run-pipeline/)), use
`scripts/pilot/rank_merged.py`, not `rank_doctors.py` with
`BBA_VERDICT_SOURCE=pipeline`.

`rank_doctors.py` with `BBA_VERDICT_SOURCE=pipeline` reads the audit store,
which holds the LLM-leg rows plus the deterministic MSBOS reservation rows
(over-reservation and reservation-review). Every order the deterministic leg
finalized outright as an auto-clear, a return or a peri-op exemption never
reaches the audit store, so a pipeline-source ranking's denominators miss
those verdicts.

`rank_merged.py` merges `report.csv` (the deterministic leg's final verdicts)
with `llm_report.json` (the LLM leg's final verdicts). The LLM verdict replaces
the deterministic one only for orders the deterministic leg routed onward
(`NEEDS_REVIEW` or `POTENTIALLY_INAPPROPRIATE`); every deterministic terminal
stands even if a stale LLM row exists for the same order. An LLM verdict for a
`REQNO` the report does not know raises an error rather than dropping silently.

Run it once per component, because the mean/min/max trigger columns are Hb for
red cells and platelet count for platelets:

```bash
uv run python scripts/pilot/rank_merged.py red_cell
uv run python scripts/pilot/rank_merged.py platelet
```

Each run writes `<component>_doctor_ranking.csv`,
`<component>_department_ranking.csv`, and `<component>_doctor_rankings.html`
to `$BBA_PILOT_WORK_DIR`, reading the same `BBA_BDVST_CSV` / `BBA_DCT_CSV`
environment variables as `rank_doctors.py` below.

## What rank_doctors.py is

The attribution chain resolves an order back to a doctor:

- An order's `REQNO` → `BDVST.DCTREQ` → the `DCT.csv` doctor registry.

The verdict source is swappable through the `VerdictSource` seam and
selectable at runtime with `BBA_VERDICT_SOURCE`: the default `human`
ranks on the 300-case human-review workbook (Sheet1, column J), and
`pipeline` ranks on full-cohort pipeline verdicts read from the audit
store (`BBA_AUDIT_STORE_DIR` + `BBA_RUN_ID` / `BBA_CODE_VERSION`).
With the pipeline source, scorecards also carry the returns terminals
(`RETURNED_NOT_TRANSFUSED` / `PERIOP_TRANSFUSION_EXEMPT`) as an
*excluded* bucket and fold `PREOP_OVER_RESERVATION` into the
inappropriate side while counting it separately as
`over_reservation_count`. To rank a pilot run's output, use
`rank_merged.py` above instead of the pipeline source: the audit store the
pipeline source reads never receives the deterministic clears, returns and
peri-op exemptions.

This is a pilot script / integration seam, not a top-level `bba`
subcommand. It is also surfaced through the `serve-dashboard` integration seam
(the attribution resolvers).

## How to run

The pilot script is `scripts/pilot/rank_doctors.py`. From the repo root:

```bash
uv run python scripts/pilot/rank_doctors.py
```

The script fails loud (exits non-zero) if any of the three input files is
missing, printing which one.

### Environment variables

| Variable | What it is | Default |
| --- | --- | --- |
| `BBA_REVIEW_XLSX` | The human-review workbook (verdict source). | `~/Downloads/Review การใช้เลือด.xlsx` |
| `BBA_BDVST_CSV` | BDVST export containing `REQNO` + `DCTREQ`. | `../Bloodbank/data/encrypted/BDVST.csv` (relative to repo root) |
| `BBA_DCT_CSV` | The `DCT.csv` doctor registry. | `../Bloodbank/data/raw/DCT.csv` |
| `BBA_PILOT_WORK_DIR` | Output directory. | `/tmp/bba_mini` |
| `BBA_VERDICT_SOURCE` | Verdict source: `human` or `pipeline`. | `human` |
| `BBA_AUDIT_STORE_DIR` | Audit-store directory (pipeline source only). | — |
| `BBA_RUN_ID` | run_id scope for store reads (pipeline source only). | — |
| `BBA_CODE_VERSION` | code-version scope for store reads (pipeline source only). | — |
| `BBA_PILOT_REPORT_CSV` | The per-order pilot `report.csv` (supplies the mean pre-transfusion trigger). Required for **every** run — human or pipeline source — and fails loud when the file is missing. | `$BBA_PILOT_WORK_DIR/report.csv` |

### Example invocation

```bash
export BBA_REVIEW_XLSX="$HOME/Downloads/Review การใช้เลือด.xlsx"
export BBA_BDVST_CSV=/path/to/BDVST.csv
export BBA_DCT_CSV=/path/to/DCT.csv
export BBA_PILOT_WORK_DIR=/tmp/bba_mini
uv run python scripts/pilot/rank_doctors.py
open "$BBA_PILOT_WORK_DIR/doctor_rankings.html"
```

## Outputs

Written to `$BBA_PILOT_WORK_DIR`:

| Output | What it is |
| --- | --- |
| `doctor_ranking.csv` | Top-10 doctors, ranked with per-bucket counts. |
| `department_ranking.csv` | Top-10 departments, ranked with per-bucket counts. |
| `doctor_rankings.html` | Self-contained page for human review. |

The script also prints a reconciliation summary to stdout: total verdicts
(with appropriate / inappropriate / unresolved counts), the ranked bucket, the
minimum-N threshold, and the number of doctor/department table rows.

## Where this lives in code

- `src/bba/attribution/`: the tested module (loaders, aggregation, ranking,
  writers).
- `scripts/pilot/rank_doctors.py`: thin glue that resolves the input paths and
  reports the reconciliation summary.
- `scripts/pilot/rank_merged.py`: merges `report.csv` and `llm_report.json`
  into one verdict per order per component, then calls the same
  `bba.attribution` ranking and writers.
