The required settings depend on the command and transport. A local audit needs `BBA_DATA_DIR`. Model submission and authenticated review require additional configuration.

<EnvVarChecklist />

## Local audit

`BBA_DATA_DIR` must be an absolute writable path for persistent audit records. The directory holds run state, sealed source snapshots, `identity.key`, audit rows, calls, reports, and analysis artifacts. Use access-controlled storage outside the repository.

`BBA_APPLICATION_CONFIG` optionally names a JSON file validated by `bba.application.config.ApplicationConfig`. Unknown fields fail validation. The defaults are `transport: "local"` and `policy_version: "repository-policy"`.

## Model review

An offline cassette configuration has this shape.

```json
{
  "policy_version": "your-approved-policy-version",
  "transport": "cassette",
  "cassette": "/srv/bba/cassettes/approved-synthetic.json"
}
```

Set `BBA_APPLICATION_CONFIG` to this file. For live mode, use `transport: "live"`, omit `cassette`, and set `allow_live_api` to `true`. Install the [live dependency](/blood_audit/en/operators/install/#install-the-live-provider-dependency) and supply `ANTHROPIC_API_KEY` through the deployment's secret mechanism. Live requests can incur provider charges.

Both model modes use these admission inputs.

| Variable | Required content |
| --- | --- |
| `BBA_PRIVACY_POLICY` | Trust-policy JSON with `key_id`, `public_key_file`, and `approved_redactor`. The approved redactor identifies `version`, a nonzero SHA-256 `model_sha`, and `gazetteer_version`. |
| `BBA_PRIVACY_ARTIFACTS` | JSON object keyed by audit ID. Each value is a `PrivacyArtifact` containing the exact redacted `evidence_chunks` and signed `attestation`. |
| `BBA_DB_URL` | Migrated Postgres checkpoint database, with the required role permissions. Use `postgresql://user@host/database`. |

The public-key file contains the 32-byte Ed25519 verification key. An approved local redaction service prepares the evidence through `RedactionAuthority.prepare`. That service holds the private signing key, approved model, and k-anonymity gate. Keep the private key outside the audit application.

Attestations bind the exact prompt, audit ID, run ID, redactor version, and passed privacy checks. Prepare them with the same bundle, package version, and application configuration used by the audit. Missing or rejected admission leaves the case for local review. A caller's assertion or a digest alone cannot authorize submission.

`enable_missing_hb_positive_evidence` and `enable_missing_platelet_defer` default to `false`. Enable either application setting only for its approved policy.

The checkpoint store accepts the plain Postgres DSN above through psycopg. The review adapter converts that DSN for SQLAlchemy internally. Do not supply a `postgresql+psycopg://` URL to the shared setting.

## Reports and dashboard attribution

`BBA_BDVST_CSV` names the matching BDVST export with `REQNO` and `DCTREQ`. `BBA_DCT_CSV` names the doctor registry. Both are required by `bba report` and `bba serve-dashboard`. `DCTREQ` identifies the physician, and the doctor's department supplies the report's ward grouping.

## Dashboard authentication

`BBA_DASHBOARD_AUTH_SECRET` must contain at least 32 UTF-8 bytes. Your trusted identity adapter and dashboard share this secret to sign and verify sessions. `BBA_DASHBOARD_PUBLIC_ORIGIN` must be the externally visible HTTPS origin.

The CLI binds to loopback behind an HTTPS proxy. It does not issue reviewer identities. See [Serve authenticated review](/blood_audit/en/operators/integration-seams/#serve-authenticated-review) for the cookie and identity contract.

## Check presence without printing values

Run a presence check on the settings required for your deployment. This prints names and status only, including for the database URL and authentication secret.

```sh
uv run python - <<'PYTHON'
import os
names = (
    "BBA_DATA_DIR", "BBA_APPLICATION_CONFIG", "BBA_PRIVACY_POLICY",
    "BBA_PRIVACY_ARTIFACTS", "BBA_DB_URL", "ANTHROPIC_API_KEY",
    "BBA_BDVST_CSV", "BBA_DCT_CSV", "BBA_DASHBOARD_AUTH_SECRET",
    "BBA_DASHBOARD_PUBLIC_ORIGIN",
)
for name in names:
    print(f"{name}: {'set' if os.environ.get(name) else 'unset'}")
PYTHON
```

An unset optional setting is expected in local mode. Presence does not establish that a configuration is valid. Keep credentials out of shell transcripts, screenshots, and issue reports.

## Pilot settings

Research scripts read a separate set of `BBA_PILOT_*` settings and feature switches. They do not configure the supported application. See [Run the pipeline](/blood_audit/en/operators/run-pipeline/) and the [pilot README](https://github.com/macsermkiat/blood_audit/blob/main/scripts/pilot/README.md) for the script-specific contract.
