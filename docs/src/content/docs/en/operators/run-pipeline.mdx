Use the supported CLI for a canonical HOSxP audit. The research pilot is a separate script workflow with its own configuration and review artifacts.

## Run the supported application

`PLATELET_LLM_ENABLED` is false in the repository configuration. If a bundle contains platelet orders that require the disabled review route, the application rejects the uncommitted work and does not mark the run complete. A local audit is not a guarantee that every platelet order can complete. Confirm the approved deployment route before selecting a platelet cohort.

```sh
export BBA_DATA_DIR=/srv/bba/data
uv run bba audit --input /srv/bba/export/BDVST.csv
```

This commits deterministic results and local review decisions without Postgres or model credentials. [First audit run](/blood_audit/en/operators/first-audit-run/) covers the bundle and expected output. [Environment variables](/blood_audit/en/operators/env-vars/) covers admitted cassette and live model modes.

For reports, evaluation, monitoring, or authenticated adjudication, use [Generate the report](/blood_audit/en/operators/generate-report/) and [Deployment integrations](/blood_audit/en/operators/integration-seams/).

## Reproduce a research pilot

The pilot scripts sample a component-specific bundle, run a deterministic pass, optionally submit structured model evidence, audit responses, and build a review page. Their settings and output layout differ from the supported application's signed-admission configuration.

Use an approved host and private work directory. The scripts can read hospital exports by default. Confirm each input path before running them. Keep inputs, workbooks, and outputs out of the repository.

The [pilot README](https://github.com/macsermkiat/blood_audit/blob/main/scripts/pilot/README.md) is the script reference. Set its `BBA_PILOT_*` and input variables before using this sequence.

```sh
uv run python scripts/pilot/sample_bundle.py
uv run python scripts/pilot/run_pipeline.py
```

These commands produce the sampled `bundle/`, `sample_manifest.csv`, and deterministic `report.csv` in the configured work directory. The deterministic report also contains the enabled returns, declared-use, and MSBOS reservation outputs.

The following model step can incur provider charges. Obtain approval and install the live dependency before invoking it.

```sh
uv run --extra live python scripts/pilot/run_llm_leg.py
uv run python scripts/pilot/audit_llm_responses.py
uv run python scripts/pilot/build_review.py
```

The model step writes `llm_report.json` and audit-store artifacts. The response audit checks parsing, truncation, reasoning-label consistency, and unexplained verdict changes. It writes findings without changing classifications. Its default code checks make no model call. Opt-in judge modes can call the provider.

The review builder requires a response audit for the exact report SHA-256 and rejects HIGH findings. `BBA_PILOT_ALLOW_UNAUDITED=1` bypasses that gate and must not be treated as a reviewed result. Keep the gate enabled for the normal workflow.

The pilot model step sends structured evidence such as diagnosis codes, laboratory values, medications, and locally extracted vital-sign numbers. It does not send raw progress or focus-note text. That scope does not establish approval to export the structured evidence.

## Rank pilot results

Use `scripts/pilot/rank_merged.py` to combine deterministic and model results for pilot ranking. See [Doctor and department ranking](/blood_audit/en/operators/doctor-ranking/) for the denominator rules and required inputs.
