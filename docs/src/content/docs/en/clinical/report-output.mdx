The monthly report summarises RBC orders from one committed audit run. Platelet orders do not enter these RBC counts or rates. The reviewer queue covers committed unresolved cases from both components.

## Files and audiences

The generator writes five committee CSVs, one own-view CSV per requested physician, a committee PDF, and `provenance.json`.

| File | Contents |
| --- | --- |
| `hospital_trend.csv` | Monthly totals and classification counts, with the inappropriate rate. |
| `ward_scorecard.csv` | The same counts grouped by ward. |
| `indication_distribution.csv` | Counts per indication code. An order can contribute to several indications. |
| `cohort_exception.csv` | Counts and inappropriate rates by clinical-context cohort. |
| `pipeline_health.csv` | Classified, review, and insufficient-evidence counts and rates. |
| `physician_own_view_<physician_id>.csv` | One physician's own totals and rate, with anonymous peer quartiles. |
| `report_<YYYY-MM-DD>.pdf` | Committee tables. The date is the first day of the report month. |
| `provenance.json` | Source-row identities and the policy, model, prompt, evidence, and redactor identifiers used. |

Own-view CSVs are separate files, each with one physician's data row. Distribute a file only to its intended recipient. The committee PDF includes a physician table and needs committee-level access controls. File separation does not enforce permissions on the output directory or delivery channel.

## Scoring and review counts

`RETURNED_NOT_TRANSFUSED` and `PERIOP_TRANSFUSION_EXEMPT` rows are excluded from scoring and from the report's `total_orders`. `PREOP_OVER_RESERVATION` counts on the inappropriate side. `INSUFFICIENT_EVIDENCE` remains a separate category.

`POTENTIALLY_INAPPROPRIATE` and `PREOP_RESERVATION_UNCONFIRMED` need an explicit classification projector. The default builder rejects these labels rather than guessing how they contribute to the four report categories.

Pipeline-health review counts include `NEEDS_REVIEW` and classified orders with `needs_human_review` set. Insufficient-evidence rows stay in their own count, including when flagged. These report metrics differ from the dashboard's unresolved human-review queue.

## Provenance and reproducibility

Each CSV data row and PDF page carries a run-level provenance summary. A run may contain deterministic results and several LLM models or prompts. The summary represents that mixture, while `provenance.json` preserves each RBC source row's exact identifiers, including excluded rows.

The evidence footer hash is a digest of sorted audit-ID and evidence-hash pairs. It is not an evidence-schema hash. For mixed prompts, `prompt_hash` is also an aggregate digest. The model field can contain a sorted JSON list. Deterministic rows use `deterministic` and can show `not-applied` for a redactor that did not run.

These records support tracing a stored answer. A new model call is not guaranteed to reproduce the original answer. Reproduction also needs the retained inputs, code, configuration, and artifacts.

Run [`bba report`](/blood_audit/en/operators/generate-report/) to produce the files. [Report schema](/blood_audit/en/reference/report-schema/) describes the stored labels and provenance fields.
