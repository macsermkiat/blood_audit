## From export to review

The application reads a completed HOSxP export and evaluates eligible red-cell
and platelet orders against the repository's policy implementation. It keeps
the supporting evidence and the policy and model provenance with each result.

1. Prepare the canonical CSV bundle and run `bba audit`.
2. Review committed results and unresolved cases in the authenticated dashboard.
3. Generate committee reports or compare committed runs for quality improvement.

The default local mode makes no model calls. Eligible unresolved red-cell
cases become local privacy review. Model execution requires signed evidence
from an approved local redaction authority and durable database checkpoints.
The platelet model route is separately disabled by default; unresolved platelet
work can prevent completion until that route is configured. The
[first-run guide](/blood_audit/en/operators/first-audit-run/) explains these limits.

Returns, declared use, and preoperative reservation checks can route an order
before the Hb or platelet rules. Routing exemptions, over-reservation findings,
and missing evidence have different meanings and denominators. Use the
[clinical policy summary](/blood_audit/en/clinical/policy-summary/) to interpret them.

## Scope and evidence

This is retrospective quality-improvement software for adult inpatients at
King Chulalongkorn Memorial Hospital. It does not authorize orders at the
point of care. Tests verify implemented software behavior; clinical validation,
approved de-identification, and deployment controls require separate evidence.

The [architecture guide](/blood_audit/en/developers/architecture/) shows the
processing stages. The [report guide](/blood_audit/en/clinical/report-output/)
explains the stored results and report limits.
