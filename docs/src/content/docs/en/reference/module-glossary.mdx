[`docs/CONTEXT.md`](https://github.com/macsermkiat/blood_audit/blob/main/docs/CONTEXT.md) describes current contracts in more detail. This glossary follows the Python modules under `src/bba`.

## Application and source data

| Module | Responsibility |
| --- | --- |
| `bba.cli` | Operator commands and command-line configuration. |
| `bba.application` | Compose the source adapter, contexts, audit execution, deferred work, and reporting operations. |
| `bba.application.source_snapshot` | Seal and verify the source snapshot used by a run. |
| `bba.ingest` | Validate exported CSVs, normalise declared fields, and record ingest completion. |
| `bba.audit_orders` | Construct auditable order identities and order timestamps. |
| `bba.component_map` | Assign a blood-component family before component-specific rules. |

The ingest schema registry contains 13 canonical tables. They are `BDVST`, `BDVSTDT`, `BDVSTST`, `BDVSTTRANS`, `BDTYPE`, `Diagnosis`, `Lab`, `Med`, `IPDADMPROGRESS`, `IPDNRFOCUSDT`, `IPTSUMOPRT`, `INCPT_OPRTACT`, and `ICD9CM`. Dictionary exports such as `DCT.csv` used for attribution are additional inputs, not another canonical ingest table.

## Classification and evidence

| Module | Responsibility |
| --- | --- |
| `bba.hb_lookup` | Select the pre-order Hb, freshness, delta-Hb windows, and bounded 24-hour minimum. |
| `bba.cohort_detector` | Assign an RBC clinical-context label and numeric threshold where applicable. |
| `bba.deterministic_classifier` | Apply RBC routing, Hb rules, bypasses, and review flags. |
| `bba.platelet_lookup` and `bba.platelet_classifier` | Select platelet counts and apply the deterministic platelet gate. |
| `bba.returns_ledger` and `bba.declared_use` | Interpret unit dispositions and declared order use. |
| `bba.preop_reservation` | Compare reservation amounts with procedure-specific reference limits. |
| `bba.evidence_bundle_builder` | Assemble evidence for an audit order. |
| `bba.deid_redactor` | Redact evidence and represent privacy-check outcomes. |
| `bba.deid_redactor.admission` | Verify signed redaction attestations before LLM submission. |
| `bba.prompt_builder` | Construct the task-specific request and evidence envelope. |
| `bba.llm_client` | Submit approved requests and retain request-bound responses and attempts. |
| `bba.quote_grounder` | Check response quotations against the supplied evidence. |
| `bba.platelet_guardrail` | Apply platelet-specific floors and structured-signal checks. |
| `bba.audit_pipeline` | Dispatch, resume, and finalise component results. |

## Stored results and review

| Module | Responsibility |
| --- | --- |
| `bba.audit_store` | Persist versioned audit results and run records. |
| `bba.review_actions` | Persist reviewer actions and access history. |
| `bba.dashboard.auth` | Validate signed reviewer sessions and session-bound CSRF tokens. |
| `bba.dashboard.adjudication` | Bind decisions to the exact run, code version, row hash, and revision. |
| `bba.report_generator` | Build RBC aggregates, physician files, PDF, and per-row provenance. |
| `bba.attribution` | Resolve ordering-physician and department attribution. |
| `bba.eval_harness` and `bba.monitoring` | Compare stored results with reviewed labels and monitor drift. |

## Terms

- `audit_id` identifies the audited order.
- `run_id` identifies a run from its source, schema, and code identity. Application runs also bind their configuration and sealed source manifest.
- `AuditRow` holds an order's immutable stored result and provenance.
- `rule_classification` is the deterministic result. `final_classification` is the stored pipeline result.
- `needs_human_review` is a review flag independent of the final classification.
- `LLM_REVIEW` describes routing. It is not a stored classification.
- `hallucination_suspect` is a review reason for evidence-grounding failures, not a claim that every model error is detectable.
- `reservation_annotation` records reservation findings on an otherwise excluded row without changing its verdict.
- `PrivacyAttestation` binds approved redacted evidence to the exact prompt and policy. The issuer retains the Ed25519 private key. The application verifies with the public key.
- `project_24h` calculates the straight-line platelet count projection from the last two usable counts.
- `reasoning_conclusion` reads the conclusion in a model response for the label-reasoning conflict check.

Runtime defaults live in `src/bba/feature_flags.py`. Pilot environment overrides apply only where the pilot scripts read them. A flag declaration does not mean that every command exposes an override.
