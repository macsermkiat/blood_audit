## Why we link out

`CONTEXT.md` is large (~3600 lines) and is updated as part of the dev
workflow. Mirroring it into MDX would force a manual sync step that
inevitably drifts. Linking to the GitHub-rendered version guarantees the
docs site shows the live glossary without divergence risk.

## Quick navigation

Common concept slugs to search for in the glossary:

- `run_id`: the SHA-256-derived idempotency key.
- `schema_fingerprint`: what makes `run_id` invariant across identical
  inputs.
- `batch_runs`: the state machine for rows routed to the LLM.
- `audit_log`: the compliance trail for every `bba audit` invocation.
- `hallucination_suspect`: the queue that catches every grounded-quote
  failure.
- `parse_warning`: non-fatal ingest issues that surface in the run summary.
- `idempotent re-run`: the contract that re-running the same input is
  a no-op.
- `returns_ledger` / `not_transfused`: the BDVSTTRANS per-unit
  disposition aggregation behind `RETURNED_NOT_TRANSFUSED`.
- `USETYPE` / `declared_use`: the order-time declared-use signal behind
  `PERIOP_TRANSFUSION_EXEMPT` (`preop_declared_exempt`).
- `MSBOS` / `preop_reservation`: the pre-op reservation audit behind
  `PREOP_OVER_RESERVATION`, including the planned-op picker and the
  OPRTACT→ICD9 bridge.
- `reservation_annotation`: the MSBOS annotation embedded on
  returns-terminal rows (annotation, never a verdict change).
- `feature_flags`: the runtime flag module; 6 of the 9 flags are
  default-ON.
- `platelet_lookup.projection` / `project_24h`: the straight-line platelet
  count projection behind indication 5's "expected to drop below 10,000 /uL
  within 24 hours" and the `platelet_trend_unsupported` guardrail.
- `llm_client.conclusion` / `reasoning_conclusion`: reads the class a
  response's own reasoning concludes, for the `label_reasoning_conflict`
  guardrail.
- `audit_llm_responses`: the pilot step (code checks, no API call by
  default) that gates `build_review.py` on a clean response audit.
- `dev_consortium`: the Claude Code dev-test reviewer tool for pilot
  responses, not a pipeline step and not a gate.
- `rank_merged`: ranks a pilot run's merged deterministic + LLM verdicts,
  one component (`red_cell` or `platelet`) at a time.
