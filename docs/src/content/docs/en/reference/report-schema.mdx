The report generator's reference schema is [`docs/report-schema.md`](https://github.com/macsermkiat/blood_audit/blob/main/docs/report-schema.md). The current builder and writers define the emitted output. This page summarises their contract.

## Output layout

```text
$BBA_DATA_DIR/reports/<run_id>/
  hospital_trend.csv
  ward_scorecard.csv
  indication_distribution.csv
  cohort_exception.csv
  pipeline_health.csv
  physician_own_view_<physician_id>.csv
  report_<YYYY-MM-DD>.pdf
  provenance.json
```

`bba report --run-id <id>` reads committed audit rows. Ward and physician attribution use `BBA_BDVST_CSV` and `BBA_DCT_CSV`. The builder selects `component = "red_cell"` before aggregation. A platelet-only run cannot produce an RBC report.

## Stored classifications and projection

The audit store accepts nine `final_classification` values.

| Stored value | Report treatment |
| --- | --- |
| `APPROPRIATE` | Appropriate count. |
| `INAPPROPRIATE` | Inappropriate count. |
| `NEEDS_REVIEW` | Review count. |
| `INSUFFICIENT_EVIDENCE` | Separate documentation-evidence count. |
| `PREOP_OVER_RESERVATION` | Projected to inappropriate. |
| `RETURNED_NOT_TRANSFUSED` | Excluded from scoring. |
| `PERIOP_TRANSFUSION_EXEMPT` | Excluded from scoring. |
| `POTENTIALLY_INAPPROPRIATE` | Requires an explicit projector. |
| `PREOP_RESERVATION_UNCONFIRMED` | Requires an explicit projector. |

`LLM_REVIEW` names a route, not a stored classification. Failed grounding records a review result and reason. `over_reservation_count` exists on the hospital, ward, and cohort aggregate models but is not a separate CSV column.

## Run summary fields

The CSV writer adds these fields to each data row, including the synthetic row for an empty section. The PDF repeats the summary on each page.

| Field | Meaning |
| --- | --- |
| `policy_version` | Policy identifier shared by the run's RBC rows. |
| `model_id` | One model identifier or a sorted JSON list when models differ. Deterministic rows use `deterministic`. |
| `redactor_version` | Redactor version, with `not-applied` included when applicable. |
| `redactor_model_sha` | Redactor checkpoint identifier, or `unavailable` when no redactor ran. |
| `prompt_hash` | Shared prompt hash, or a digest of sorted audit-ID and prompt-hash pairs for mixed prompts. |
| `evidence_bundle_hash` | Digest of sorted audit-ID and row-specific evidence-hash pairs. |

The builder validates code version, policy, local month, and applied-redactor identity before excluding non-scorable RBC rows. Model or prompt differences are represented in the summary and per-row provenance rather than attributed to a single model.

## Per-row provenance

`provenance.json` contains `audit_id`, `run_id`, `code_version_slug`, `model_id`, `policy_version`, `prompt_hash`, `evidence_bundle_hash`, `redactor_version`, and `redactor_model_sha` for every RBC source row, including excluded rows. Aggregate CSV rows contain the summary fields above, not each underlying order's complete provenance.

## Month and rates

`ReportInputs.month` is the first day of the month. The interval is half-open, from the local month start to the next local month start in Asia/Bangkok. Stored timestamps are UTC.

The inappropriate rate is `inappropriate / total_orders`, after component filtering, exclusions, and classification projection. The indication shares can sum above one because one order can have several indication codes. Physician peer quartiles use all physicians represented in the report month, even when only a subset of own-view files is requested.
