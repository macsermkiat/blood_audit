---

รายงานรายเดือนสรุปคำสั่ง RBC จาก audit run ที่บันทึกแล้วหนึ่งชุด ไม่รวมเกล็ดเลือดในจำนวนหรืออัตราของ RBC ส่วนคิวทบทวนแสดงกรณีที่บันทึกแล้วและยังไม่จบการทบทวนจากทั้งสองส่วนประกอบ

## ไฟล์ที่สร้าง

ระบบสร้าง CSV สำหรับคณะกรรมการห้าไฟล์ ไฟล์สำหรับแพทย์แต่ละคน PDF สำหรับคณะกรรมการ และ `provenance.json`

| ไฟล์ | เนื้อหา |
| --- | --- |
| `hospital_trend.csv` | จำนวนคำสั่งและผลจำแนกรายเดือน พร้อมอัตรา inappropriate |
| `ward_scorecard.csv` | จำนวนและอัตราแยกตาม ward |
| `indication_distribution.csv` | จำนวนตามข้อบ่งชี้ คำสั่งเดียวอาจนับในหลายข้อบ่งชี้ |
| `cohort_exception.csv` | จำนวนและอัตราตาม cohort |
| `pipeline_health.csv` | จำนวนและอัตราของผลที่จำแนกแล้ว ผลที่ต้องทบทวน และหลักฐานไม่พอ |
| `physician_own_view_<physician_id>.csv` | ข้อมูลของแพทย์หนึ่งคนพร้อม quartile ของกลุ่มเทียบ โดยไม่แสดงอัตรารายบุคคลของแพทย์อื่น |
| `report_<YYYY-MM-DD>.pdf` | ตารางสำหรับคณะกรรมการ วันที่ในชื่อเป็นวันแรกของเดือนรายงาน |
| `provenance.json` | รหัสแถวต้นทางและข้อมูล policy, model, prompt, evidence และ redactor |

CSV รายแพทย์มีข้อมูลหนึ่งแถวต่อไฟล์ ควรส่งให้เจ้าของข้อมูลเท่านั้น PDF สำหรับคณะกรรมการมีตารางรายแพทย์ด้วย จึงต้องควบคุมสิทธิ์เข้าถึง การแยกไฟล์ไม่ได้กำหนดสิทธิ์ของโฟลเดอร์หรือช่องทางส่งให้เอง

## กฎการนับ

`RETURNED_NOT_TRANSFUSED` และ `PERIOP_TRANSFUSION_EXEMPT` ไม่รวมในคะแนนหรือ `total_orders` ส่วน `PREOP_OVER_RESERVATION` นับฝั่ง inappropriate และ `INSUFFICIENT_EVIDENCE` แยกเป็นอีกกลุ่ม

`POTENTIALLY_INAPPROPRIATE` และ `PREOP_RESERVATION_UNCONFIRMED` ต้องมีตัวแปลง classification ที่กำหนดชัดเจน ตัวสร้างรายงานเริ่มต้นจะปฏิเสธแทนการเดาว่าควรรวมในกลุ่มใด

จำนวนที่ต้องทบทวนใน pipeline health รวม `NEEDS_REVIEW` และผลที่จำแนกแล้วแต่มี `needs_human_review` ผลที่หลักฐานไม่พอยังนับเฉพาะกลุ่มของตนแม้มี flag จึงใช้ความหมายต่างจากคิวที่รอคนตัดสินใน dashboard

## ที่มาของผล

ทุกแถว CSV และทุกหน้า PDF มีข้อมูลสรุปที่มาระดับ run ชุดเดียวอาจมีทั้งผลจากกฎและ LLM หลายรุ่นหรือหลาย prompt ข้อมูลสรุปแสดงความหลากหลายนั้น ส่วน `provenance.json` เก็บค่าที่ใช้จริงต่อแถว RBC รวมแถวที่ยกเว้นจากคะแนน

`evidence_bundle_hash` ในส่วนสรุปเป็น hash ของคู่ audit ID และ evidence hash ที่เรียงแล้ว ไม่ใช่ hash ของ schema หากมีหลาย prompt ค่า `prompt_hash` เป็น hash รวมเช่นกัน `model_id` อาจเป็น JSON list ที่เรียงแล้ว แถวจากกฎใช้ `deterministic` และอาจใช้ `not-applied` สำหรับ redactor ที่ไม่ได้ทำงาน

ข้อมูลเหล่านี้ช่วยตรวจย้อนคำตอบที่เก็บไว้ การเรียกโมเดลใหม่ไม่ได้รับประกันว่าจะได้คำตอบเดิม ต้องเก็บข้อมูลเข้า โค้ด การตั้งค่า และ artifact สำหรับการตรวจสอบด้วย

ใช้ [`bba report`](/blood_audit/th/operators/generate-report/) เพื่อสร้างไฟล์ ดูความหมายฟิลด์ที่ [โครงสร้างรายงาน](/blood_audit/th/reference/report-schema/)
