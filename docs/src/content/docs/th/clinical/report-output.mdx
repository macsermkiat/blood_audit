## ไฟล์หลัก

| ไฟล์ | ผู้ใช้หลัก | ใช้ทำอะไร |
| --- | --- | --- |
| `hospital_trend.csv` | QI committee | ดูแนวโน้มระดับโรงพยาบาล |
| `ward_scorecard.csv` | QI committee | ดูรูปแบบระดับ ward โดยไม่ใช้เป็นบทลงโทษ |
| `indication_breakdown.csv` | QI committee | แยกตาม indication |
| `cohort_exception.csv` | QI committee | ดูบริบททางคลินิก/threshold ที่ผิดปกติ |
| `pipeline_health.csv` | IT + QI | ติดตาม failures, NEEDS_REVIEW และ grounding issues |
| `physician_own_view/*.csv` | แพทย์ผู้ทบทวน | ให้แพทย์ดูเฉพาะรายการของตนเอง |

## คำสั่งที่นับและไม่นับ

คำสั่งที่ `final_classification` เป็น `RETURNED_NOT_TRANSFUSED` หรือ
`PERIOP_TRANSFUSION_EXEMPT` ถูกตัดออกจากการคิดคะแนนความเหมาะสม
ไม่ทำให้อัตราของ ward หรือของแพทย์สูงขึ้นหรือเจือจางลง เพราะไม่มี
การให้เลือดที่ถูกตัดสิน ส่วนแถว `PREOP_OVER_RESERVATION`
คิดคะแนนอยู่ฝั่ง inappropriate

`INSUFFICIENT_EVIDENCE` ต้องไม่ถูกรวมเข้า `INAPPROPRIATE` เพราะเป็น
คนละความหมาย ข้อมูลไม่พอคือปัญหาเอกสารและหลักฐาน ไม่ใช่การตัดสินว่า
ให้เลือดไม่เหมาะสม

## กฎ privacy

Physician own-view ต้องแยกไฟล์ต่อแพทย์ ห้ามรวมเป็นไฟล์เดียวที่ทุกคน
เห็นกันหมด แต่ละไฟล์มีข้อมูลแถวเดียว รายงานสำหรับคณะกรรมการควรเป็น
aggregate หรือ de-identified ตามขอบเขตที่กำหนด

## ทำซ้ำได้

ทุกแถว CSV และทุกหน้า PDF บันทึกว่าใช้ policy เวอร์ชันใด โมเดลใด และ
หลักฐานชุดใดในการตัดสิน ผู้ตรวจในภายหลังจึงย้อนกลับไปสร้างผลเดิมได้
จากข้อมูลและ code ชุดเดียวกัน ชื่อฟิลด์ทั้งหมดอยู่ที่
[สร้างรายงาน](/blood_audit/th/operators/generate-report/)
