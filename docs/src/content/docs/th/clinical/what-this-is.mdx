## วิธีทบทวนแต่ละคำสั่ง

ระบบใช้กฎที่กำหนดไว้ก่อน บางคำสั่งได้ผลสรุปในขั้นนี้ ส่วนคำสั่งที่ต้องตีความสามารถส่งให้ LLM ได้เมื่อผ่านการตรวจความเป็นส่วนตัวและหลักฐาน คำว่า cohort หมายถึงบริบททางคลินิกของคำสั่งที่ใช้เลือกเกณฑ์ Hb ไม่ใช่กลุ่มผู้ป่วยถาวร

ผลหลักมี `APPROPRIATE`, `INAPPROPRIATE`, `NEEDS_REVIEW`, `INSUFFICIENT_EVIDENCE` และ `POTENTIALLY_INAPPROPRIATE` นอกจากนี้ยังมีผลสำหรับเลือดที่คืน การยกเว้นกรณีผ่าตัด และการจองเลือด ดูรายละเอียดที่ [สรุปนโยบาย](/blood_audit/th/clinical/policy-summary/)

เส้นทาง LLM สำหรับเกล็ดเลือดปิดอยู่โดยค่าเริ่มต้น เมื่อปิด เส้นทาง pipeline จะไม่ส่งคืนแถวเกล็ดเลือดที่ยังสรุปไม่ได้ แอปพลิเคชันตรวจพบผลที่ขาดและปฏิเสธ audit ที่ไม่ครบ จึงต้องจัดการการตั้งค่านี้ก่อนใช้กับชุดคำสั่งที่มีกรณีดังกล่าว

## การตรวจหลักฐานและการทบทวนโดยคน

ระบบตรวจข้อความอ้างอิงจาก LLM และใช้ guardrail ก่อนเก็บผล หากตรวจหลักฐานไม่ผ่าน ระบบจะเก็บกรณีไว้ให้ทบทวน เช่น กำหนด `review_reason = "hallucination_suspect"` การตรวจเหล่านี้ลดความผิดพลาดบางรูปแบบ แต่ไม่ได้ยืนยันความถูกต้องทางคลินิกหรือแทนการตรวจสอบโดยแพทย์

หน้าทบทวนแสดงกรณี RBC และเกล็ดเลือดที่บันทึกแล้วและยังต้องให้คนทบทวน ผู้ทบทวนสามารถยืนยันผล เปลี่ยนผลพร้อมเหตุผล หรือส่งต่อผู้เชี่ยวชาญ ประวัติการตัดสินผูกกับแถวผลและเวอร์ชันที่ใช้จริง การใช้งานที่ติดตั้งจริงต้องมีระบบยืนยันตัวตนที่เชื่อถือได้เชื่อมต่ออยู่

## ผลลัพธ์และขอบเขต

รายงานรายเดือนสรุป RBC และแยกไฟล์สำหรับแพทย์แต่ละคน เกล็ดเลือดไม่รวมในอัตราของ RBC ดู [ผลลัพธ์รายงาน](/blood_audit/th/clinical/report-output/) สำหรับกฎการนับ

ระบบนี้ใช้พัฒนาคุณภาพย้อนหลัง ไม่อนุมัติคำสั่งให้เลือด ณ จุดดูแลและไม่ส่งคำแนะนำรักษาแบบทันที การตรวจสอบทางคลินิกและการอนุมัติจากสถาบันเป็นงานแยกจากการพัฒนาซอฟต์แวร์
