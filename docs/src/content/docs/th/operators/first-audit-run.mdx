ขั้นตอนนี้บันทึกผลที่กฎตัดสินได้ และส่งกรณีที่ต้องใช้หลักฐานสำหรับโมเดลให้คนทบทวน ใช้ข้อมูลสังเคราะห์เพื่อตรวจการติดตั้ง หรือใช้ข้อมูลโรงพยาบาลบนเครื่องที่ได้รับอนุญาต

## เตรียมชุดข้อมูล

วาง [CSV มาตรฐานทั้ง 13 ไฟล์](/blood_audit/th/operators/ingest-csv/#expected-tables) ไว้ข้าง `BDVST.csv` กรองกลุ่มผู้ใหญ่ตามขอบเขตที่อนุมัติตั้งแต่ขั้นส่งออก และเก็บข้อมูลไว้นอก repository

เลือกพื้นที่ถาวรที่จำกัดสิทธิ์ หากใช้พื้นที่เดิม ให้ตรวจเจ้าของและสิทธิ์ก่อน แอปจะปฏิเสธไฟล์คลินิกเดิมที่เปิดสิทธิ์กว้างเกินไป

```sh
export BBA_DATA_DIR=/srv/bba/data
```

ตัวอย่างนี้ใช้ `/srv/bba/export` เป็นที่วางชุดข้อมูล เปลี่ยนทั้งสองพาธให้ตรงกับพื้นที่ที่อนุมัติ สำหรับครั้งแรกให้ใช้ค่าเริ่มต้นของโหมด local หากมี `BBA_APPLICATION_CONFIG` อยู่แล้ว ให้ตรวจว่าไฟล์นั้นเลือกโหมดใด

## ตรวจรูปแบบข้อมูล

ขั้นนี้ทำหรือข้ามก็ได้ คำสั่งตรวจ header และการปรับรูปแบบแถว จากนั้นเขียน ingest completion marker โดยยังไม่จัดประเภทคำสั่งเลือด

```sh
uv run bba ingest /srv/bba/export/BDVST.csv
```

เมื่อสำเร็จจะมี log `ingest.complete` หากขาดไฟล์หรือคอลัมน์ที่จำเป็น คำสั่งจะหยุด การรัน audit จะตรวจ snapshot ของข้อมูลอีกครั้ง จึงไม่จำเป็นต้องรัน ingest แยกทุกครั้ง

## บันทึกผลการตรวจ

ค่า `PLATELET_LLM_ENABLED` ใน repository เป็น false หากมีคำสั่งเกล็ดเลือดที่ต้องเข้าเส้นทางทบทวนซึ่งยังปิดอยู่ ระบบจะหยุดเมื่อพบงานที่ยังบันทึกไม่ครบ และไม่สร้าง completion marker ตรวจเส้นทางที่อนุมัติก่อนใช้กลุ่มข้อมูลเกล็ดเลือด

```sh
uv run bba audit --input /srv/bba/export/BDVST.csv
```

ระบบเก็บ snapshot ของข้อมูล ประกอบคำสั่งเลือด จัดประเภท และบันทึก `AuditRow` ไว้ใต้ `$BBA_DATA_DIR/audit_store` จำนวนงานที่เสร็จนับจากแถวผลการตรวจที่บันทึกแล้ว หากไม่มีคำสั่งที่อยู่ในขอบเขต คำสั่งจะไม่บันทึกว่ารอบนั้นเสร็จ

จด run ID จาก structured log เมื่อสำเร็จจะมี `audit.complete` พร้อมจำนวนแถว กรณีที่ต้องใช้โมเดลจะคงเป็น `NEEDS_REVIEW` พร้อม `privacy_admission_failed` ในโหมด local กรณีเหล่านี้ยังไม่ได้รับการตัดสินจากโมเดล

ครั้งแรกระบบสร้าง `identity.key` สำหรับรหัสแทนผู้ป่วยและการนอนโรงพยาบาลด้วย HMAC สำรองคีย์พร้อมไดเรกทอรีข้อมูล


## ตรวจการรันซ้ำ

รันคำสั่ง audit เดิมด้วยข้อมูล การตั้งค่า และรุ่นโค้ดเดิม หากรอบนั้นเสร็จแล้วจะมี log `audit.noop` และใช้ผลที่บันทึกไว้

`--force` ข้ามการตรวจว่ารอบเสร็จแล้วและบันทึกการสั่งรันซ้ำ แต่ไม่เขียนทับผลที่ยืนยันแล้ว หากเปลี่ยนนโยบายหรือเพิ่งได้หลักฐานที่อนุมัติ ให้ใช้ policy version ใหม่และเริ่มรอบใหม่ ดู [คำสั่ง audit](/blood_audit/th/operators/audit-command/)

## สร้างรายงานจากผลที่บันทึกแล้ว

รายงานรายเดือนใช้เฉพาะเม็ดเลือดแดงและไม่รับรอบที่มีแต่เกล็ดเลือด ต้องใช้ไฟล์คำสั่งเลือดและทะเบียนแพทย์ที่ตรงกัน

```sh
export BBA_BDVST_CSV=/srv/bba/export/BDVST.csv
export BBA_DCT_CSV=/srv/bba/export/DCT.csv
uv run bba report --run-id RUN_ID --format html
```

แทน `RUN_ID` ด้วย ID ที่จดไว้ คำสั่งจะแสดงพาธไฟล์ HTML เก็บรายงานในช่องทางทบทวนที่อนุมัติ ดูรูปแบบ JSON และ PDF ที่ [สร้างรายงาน](/blood_audit/th/operators/generate-report/)
