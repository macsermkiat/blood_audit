ใช้ CLI ที่รองรับเมื่อตรวจชุดข้อมูล HOSxP มาตรฐาน ส่วน research pilot เป็นสคริปต์อีกชุดที่มีการตั้งค่าและผลทบทวนของตนเอง

## รันแอปที่รองรับ

ค่า `PLATELET_LLM_ENABLED` ใน repository เป็น false หากมีงานเกล็ดเลือดที่ต้องเข้าเส้นทางทบทวนซึ่งยังปิดอยู่ คำสั่งจะหยุดเมื่อพบงานที่บันทึกไม่ครบ และไม่บันทึกว่ารอบเสร็จแล้ว

```sh
export BBA_DATA_DIR=/srv/bba/data
uv run bba audit --input /srv/bba/export/BDVST.csv
```

โหมดนี้บันทึกผลจากกฎและกรณีที่ต้องให้คนทบทวนในเครื่อง โดยไม่ต้องใช้ Postgres หรือ credentials ของโมเดล ดูชุดข้อมูลและผลที่คาดได้ที่ [ตรวจข้อมูลครั้งแรก](/blood_audit/th/operators/first-audit-run/) และดูโหมด cassette กับ live ที่ [ตัวแปรแวดล้อม](/blood_audit/th/operators/env-vars/)


ดูรายงาน การประเมิน การเปรียบเทียบรอบ และการตัดสินผลที่ [สร้างรายงาน](/blood_audit/th/operators/generate-report/) และ [การเชื่อมต่อระบบ](/blood_audit/th/operators/integration-seams/)

## ทำซ้ำ research pilot

สคริปต์ pilot สุ่ม bundle แยกตามผลิตภัณฑ์ รันกฎ ส่งหลักฐานแบบมีโครงสร้างให้โมเดลเมื่อเลือกใช้ ตรวจคำตอบ และสร้างหน้าทบทวน การตั้งค่าและที่เก็บผลต่างจากแอปที่ใช้ signed admission

ใช้เครื่องที่ได้รับอนุญาตและ work directory ที่จำกัดสิทธิ์ ค่าเริ่มต้นของสคริปต์บางตัวอ่านไฟล์โรงพยาบาล ตรวจทุกพาธก่อนรัน และเก็บข้อมูล workbook กับผลลัพธ์ไว้นอก repository

[pilot README](https://github.com/macsermkiat/blood_audit/blob/main/scripts/pilot/README.md) อธิบายค่าของแต่ละสคริปต์ ตั้ง `BBA_PILOT_*` และตัวแปรข้อมูลนำเข้าก่อนใช้ลำดับนี้

```sh
uv run python scripts/pilot/sample_bundle.py
uv run python scripts/pilot/run_pipeline.py
```

จะได้ `bundle/`, `sample_manifest.csv` และ `report.csv` จากกฎใน work directory ที่กำหนด deterministic report มีผลจาก returns declared-use และ MSBOS reservation ที่เปิดใช้อยู่ด้วย

ขั้นโมเดลต่อไปอาจมีค่าใช้จ่าย ขออนุมัติและติดตั้ง live dependency ก่อนเรียก

```sh
uv run --extra live python scripts/pilot/run_llm_leg.py
uv run python scripts/pilot/audit_llm_responses.py
uv run python scripts/pilot/build_review.py
```

ขั้นโมเดลเขียน `llm_report.json` และ audit-store artifacts response audit ตรวจการ parse คำตอบถูกตัด เหตุผลขัดกับ label และการเปลี่ยนผลโดยไม่มีเหตุผลบันทึก โดยไม่แก้ classification การตรวจด้วยโค้ดตามค่าเริ่มต้นไม่เรียกโมเดล ส่วน judge mode ที่เลือกเพิ่มอาจเรียกผู้ให้บริการ

review builder ต้องมี response audit ที่ตรงกับ SHA-256 ของรายงานและไม่มี HIGH finding ค่า `BBA_PILOT_ALLOW_UNAUDITED=1` ข้ามการตรวจนี้ จึงห้ามถือว่าผลที่ได้ผ่านการทบทวนแล้ว ใช้การตรวจตามปกติโดยไม่เปิดค่านี้

โมเดล pilot รับหลักฐานแบบมีโครงสร้าง เช่น รหัสวินิจฉัย ผลตรวจ ยา และตัวเลข vital signs ที่สกัดในเครื่อง ไม่ส่งข้อความ progress note หรือ focus note ดิบ ขอบเขตนี้ไม่ได้ยืนยันว่าข้อมูลแบบมีโครงสร้างได้รับอนุมัติให้ส่งออกแล้ว

## จัดอันดับผล pilot
