เก็บข้อมูลนำเข้าและผลจัดอันดับในช่องทางทบทวนที่อนุมัติ ไฟล์เหล่านี้เชื่อมตัวตนแพทย์กับผลประเมินทางคลินิก การเข้ารหัสรหัสผู้ป่วยไม่ได้ทำให้เผยแพร่ไฟล์ได้

## จัดอันดับผล pilot

ใช้ `rank_merged.py` สำหรับ [research pilot](/blood_audit/th/operators/run-pipeline/) สคริปต์รวมผลจากกฎใน `report.csv` กับ `llm_report.json` ก่อนคำนวณสรุป

audit store ของขั้นโมเดลใน pilot ไม่มีผลที่กฎตัดสินจบหลายประเภท หากอ่านเฉพาะ store นี้ ตัวหารจะขาดคำสั่งเหล่านั้น ข้อจำกัดนี้เป็นของสคริปต์ pilot ไม่ใช่การประกอบผลทั้งหมดของแอปที่รองรับ

กำหนด `BBA_PILOT_WORK_DIR` เป็นไดเรกทอรีผล pilot พร้อม `BBA_BDVST_CSV` และ `BBA_DCT_CSV` ที่ตรงกัน รันแต่ละผลิตภัณฑ์แยกกัน เพราะสถิติ trigger ใช้ผลตรวจคนละชนิด

```sh
uv run python scripts/pilot/rank_merged.py red_cell
uv run python scripts/pilot/rank_merged.py platelet
```

ผลโมเดลจะแทนผลจากกฎเฉพาะคำสั่งที่กฎส่งไปทบทวนต่อ ผลที่กฎตัดสินจบแล้วยังคงเดิม หากโมเดลมี `REQNO` ที่ไม่อยู่ในรายงาน สคริปต์จะหยุด

แต่ละผลิตภัณฑ์เขียน `<component>_doctor_ranking.csv`, `<component>_department_ranking.csv` และ `<component>_doctor_rankings.html` ใต้ `BBA_PILOT_WORK_DIR`

## จัดอันดับจากคนทบทวนหรือผลที่บันทึกใน store

`rank_doctors.py` เลือกแหล่งผลด้วย `BBA_VERDICT_SOURCE` ค่าเริ่มต้น `human` อ่าน Sheet1 คอลัมน์ J ของ workbook ส่วน `pipeline` อ่านแถวเม็ดเลือดแดงของรอบที่เลือกจาก audit store ใช้แหล่งนี้เมื่อแถวที่บันทึกครอบคลุมประชากรที่ต้องการจัดอันดับ

```sh
export BBA_REVIEW_XLSX=/srv/bba/reviewed-labels.xlsx
export BBA_BDVST_CSV=/srv/bba/export/BDVST.csv
export BBA_DCT_CSV=/srv/bba/export/DCT.csv
export BBA_PILOT_WORK_DIR=/srv/bba/pilot
export BBA_PILOT_REPORT_CSV=/srv/bba/pilot/report.csv
uv run python scripts/pilot/rank_doctors.py
```

กำหนดพาธเองเพื่อหลีกเลี่ยงค่าเริ่มต้นของงานวิจัยที่ชี้ไป workbook ในเครื่องและข้อมูล Bloodbank ข้าง repository หากขาดไฟล์ที่ต้องใช้ สคริปต์จะหยุด

| ตัวแปร | การใช้งาน |
| --- | --- |
| `BBA_VERDICT_SOURCE` | ค่าเริ่มต้น `human` หรือเลือก `pipeline` |
| `BBA_REVIEW_XLSX` | Workbook ของแหล่ง human ค่าเริ่มต้น `~/Downloads/Review การใช้เลือด.xlsx` |
| `BBA_BDVST_CSV` | ไฟล์คำสั่งที่มี `REQNO` และ `DCTREQ` ค่าเริ่มต้นงานวิจัย `../Bloodbank/data/encrypted/BDVST.csv` |
| `BBA_DCT_CSV` | ทะเบียนแพทย์ ค่าเริ่มต้นงานวิจัย `../Bloodbank/data/raw/DCT.csv` |
| `BBA_PILOT_WORK_DIR` | ไดเรกทอรีผล ค่าเริ่มต้น `/tmp/bba_mini` |
| `BBA_PILOT_REPORT_CSV` | ข้อมูล trigger รายคำสั่ง ต้องใช้ทั้งสองแหล่ง ค่าเริ่มต้น `report.csv` ใน work directory |
| `BBA_AUDIT_STORE_DIR` | Root ของ audit store สำหรับ pipeline หากไม่ตั้งจะใช้ `$BBA_DATA_DIR/audit_store` |
| `BBA_RUN_ID` | ต้องระบุรอบเดียวเมื่อใช้ pipeline |
| `BBA_CODE_VERSION` | รุ่นโค้ดของ pipeline เลือกได้ ใช้เมื่อรอบที่เลือกมีหลายรุ่นจนแยกผลไม่ได้ |

สคริปต์เขียน `doctor_ranking.csv`, `department_ranking.csv` และ `doctor_rankings.html` ใน work directory และแสดงสรุปจำนวน verdict กลุ่มที่จัดอันดับ เกณฑ์จำนวนตัวอย่างขั้นต่ำ และจำนวนแถวผล

## ตีความแพทย์และแผนก

`bba.attribution` จัดอันดับแพทย์และแผนก 10 อันดับแรก โดยแบ่งผลเป็นเหมาะสม ไม่เหมาะสม และยังไม่สรุป ระบบเชื่อม `REQNO` กับ `BDVST.DCTREQ` แล้วค้น `DCT.csv` แผนกจึงหมายถึงแผนกของแพทย์ผู้สั่ง

แหล่ง pipeline นับ `RETURNED_NOT_TRANSFUSED` และ `PERIOP_TRANSFUSION_EXEMPT` ในกลุ่มไม่นับคะแนน ส่วน `PREOP_OVER_RESERVATION` รวมอยู่ฝั่งไม่เหมาะสมและนับ `over_reservation_count` แยกด้วย ตรวจประชากรของแหล่งข้อมูลก่อนตีความอัตรา

สคริปต์จัดอันดับแยกจาก `bba report` แต่รายงานและ dashboard ใช้ attribution loaders ชุดเดียวกัน ดูไฟล์ที่ต้องใช้ที่ [สร้างรายงาน](/blood_audit/th/operators/generate-report/)
