---

`bba audit` ตรวจชุดข้อมูล HOSxP ประกอบคำสั่งเลือด และบันทึกผลการจัดประเภท คำสั่งอ่านไฟล์ส่งออกและเขียนผลในเครื่อง โดยไม่แก้ฐานข้อมูล HOSxP

```sh
uv run bba audit --input /srv/bba/export/BDVST.csv
uv run bba audit --run-id RUN_ID
```

## อาร์กิวเมนต์

| ตัวเลือก | การทำงาน |
| --- | --- |
| `--input PATH` | พาธ `BDVST.csv` ที่อยู่กับ CSV มาตรฐานอื่น คำนวณ run identity จากชุดข้อมูล schema รุ่นโค้ด และไฟล์ตั้งค่าแอปที่ระบุ |
| `--run-id ID` | เลือกรอบที่มีบันทึกไว้ ทำงานที่ค้างต่อจาก source snapshot เมื่อการตั้งค่ายังตรงกัน หากเสร็จแล้วจะไม่ทำซ้ำ เว้นแต่ใช้ `--force` |
| `--force` | ข้ามการตรวจว่ารอบเสร็จแล้ว และเพิ่มรายการ `audit_log` ที่มี `idempotency_override=true` ผลที่บันทึกแล้วกับ request manifest ยังคงแก้ทับไม่ได้ |

ต้องเลือก `--input` หรือ `--run-id` อย่างใดอย่างหนึ่ง รอบที่ใช้ run ID เดียวกันใช้ lock เดียวกัน ส่วนคนละ run ID ทำงานพร้อมกันได้

## การตั้งค่าและผลลัพธ์

ต้องมี `BBA_DATA_DIR` หากไม่ระบุ `BBA_APPLICATION_CONFIG` จะใช้โหมด local และ policy version `repository-policy` ระบบบันทึกผลจากกฎ ส่วนกรณีที่ต้องใช้โมเดลจะเป็น `NEEDS_REVIEW` พร้อม `privacy_admission_failed` โดยไม่เรียกโมเดล

ไฟล์ตั้งค่า JSON ที่ระบุจะมีส่วนใน run identity เลือก transport ได้เป็น `local`, `cassette` หรือ `live` การส่งให้โมเดลต้องมีหลักฐานที่ผ่านการตรวจลายมือชื่อและ Postgres สำหรับ checkpoint ดู [ตัวแปรแวดล้อม](/blood_audit/th/operators/env-vars/)

completion marker จะเกิดหลังบันทึก ID ของ `AuditRow` แล้ว ตารางที่นำเข้าไม่นับเป็นผลการตรวจ หากไม่มีกลุ่มข้อมูลที่เข้าเกณฑ์ คำสั่งจะหยุด คำสั่งเกล็ดเลือดที่ถูกระงับในช่วง MTP จะไม่มี audit row ตามการออกแบบ

`PLATELET_LLM_ENABLED` ใน repository เป็น false หากยังมีงานเกล็ดเลือดที่ต้องเข้าเส้นทางทบทวนซึ่งปิดอยู่ แอปจะไม่บันทึกว่ารอบเสร็จแล้ว

## Run identity และหลักฐานที่เก็บ

เนื้อหา CSV มาตรฐานทั้งหมด schema fingerprint และรุ่น package ใช้กำหนด identity พื้นฐาน ไฟล์ตั้งค่าแอปที่ระบุจะมีส่วนเพิ่มใน audit identity ด้วย การเปลี่ยน CSV ไฟล์รองจึงอาจสร้าง run ID ใหม่

ก่อนจัดประเภท แอปคัดลอกข้อมูลเป็น source snapshot ที่แก้ไม่ได้ ไฟล์และ manifest ใช้ mode 0400 ภายในไดเรกทอรีของเจ้าของที่ใช้ mode 0500 ระบบตรวจ identity ของข้อมูล schema การตั้งค่า และรุ่นโค้ดก่อนใช้ snapshot การแก้ไฟล์โดยผู้ส่งออกจึงไม่เปลี่ยนข้อมูลของรอบที่กำลังทำงาน

แถวผลการตรวจ calls request manifests และ analysis artifacts ทั่วไปใช้ไฟล์และไดเรกทอรีที่ให้สิทธิ์เฉพาะเจ้าของ แอปปฏิเสธพื้นที่เดิมที่เปิดสิทธิ์กว้างเกินไปหรือใช้ final symlink สำรอง `identity.key` source bindings snapshot และผลที่บันทึกแล้วตามนโยบายเดียวกัน

## ทำงานที่ขัดจังหวะต่อ

ใช้ `--run-id` และไฟล์ตั้งค่าเดิม snapshot ที่เก็บไว้ช่วยให้ทำต่อได้แม้ไฟล์ส่งออกต้นฉบับถูกนำออกแล้ว

batch ที่ยืนยันการส่งแล้วกู้คืนจาก identity และลำดับ calls ที่บันทึกไว้ได้ หากไม่ทราบแน่ชัดว่าผู้ให้บริการรับคำขอหรือไม่ ผู้ดูแลต้องตรวจสอบผลก่อน ระบบไม่ส่งคำขอที่ไม่ทราบผลซ้ำโดยอัตโนมัติ เก็บ checkpoint ไว้ระหว่างตรวจสอบ

## ตรวจด้วยนโยบายหรือหลักฐานใหม่

ใช้ `policy_version` ที่อนุมัติใหม่ใน `BBA_APPLICATION_CONFIG` และเตรียมหลักฐานที่ลงลายมือชื่อสำหรับ run identity ใหม่นั้น เก็บเนื้อหา cassette ให้คงที่ตลอดรอบ

การเพิ่มไฟล์อนุมัติหลังรอบ local เสร็จไม่เปลี่ยนผลเดิม `--force` ไม่ได้อนุญาตให้เขียนทับ classification request manifest หรือผลการตรวจสิทธิ์ส่งหลักฐานที่เสร็จแล้ว
