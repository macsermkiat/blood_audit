ใช้ `bba audit` ตรวจข้อมูลส่งออกจาก HOSxP ย้อนหลังและบันทึกผลการจัดประเภท เริ่มจาก [ติดตั้ง](/blood_audit/th/operators/install/) และ [ตรวจข้อมูลครั้งแรก](/blood_audit/th/operators/first-audit-run/)

โหมด local ต้องใช้ Python, uv, ชุดข้อมูลครบถ้วน และพื้นที่เก็บข้อมูลถาวรที่จำกัดสิทธิ์ ไม่ต้องใช้ API key หรือ Postgres ระบบบันทึกผลที่กฎตัดสินได้ ส่วนกรณีที่ต้องใช้หลักฐานสำหรับโมเดลจะเป็น `NEEDS_REVIEW` พร้อมเหตุผล `privacy_admission_failed`

## เตรียมข้อมูลและพื้นที่เก็บ

วาง CSV มาตรฐานทั้ง 13 ไฟล์ไว้ด้วยกัน ผู้ส่งออกข้อมูลต้องกรองกลุ่มผู้ใหญ่ตามขอบเขตที่อนุมัติก่อน เพราะชุดข้อมูลนี้ไม่มีคอลัมน์อายุ ดู [ตารางข้อมูลนำเข้า](/blood_audit/th/operators/ingest-csv/#expected-tables)

กำหนด `BBA_DATA_DIR` ให้เป็นพื้นที่ถาวรของบัญชีที่ใช้รันระบบ สำรอง `identity.key` พร้อมบันทึกการตรวจ เพราะคีย์นี้ใช้สร้างรหัสแทนผู้ป่วยและการนอนโรงพยาบาลให้คงที่ กำหนดอายุการเก็บและสิทธิ์เข้าถึง snapshot รายงาน และ log ตามนโยบายข้อมูลคลินิก

## เพิ่มการทบทวนด้วยโมเดล

โหมด cassette และ live ต้องมีไฟล์ตั้งค่าแอป นโยบายตรวจลายมือชื่อ หลักฐานที่ลงลายมือชื่อแล้ว และ Postgres ที่ใช้เก็บ checkpoint โหมด live ต้องติดตั้ง dependency เพิ่ม มี API key และตั้ง `allow_live_api` เป็น `true`

บริการลบข้อมูลระบุตัวบุคคลที่ได้รับอนุมัติเป็นผู้ถือโมเดลและ private signing key แอปตรวจเลือดรับเฉพาะ public key และหลักฐานที่ลงลายมือชื่อ CLI ไม่ได้ติดตั้งบริการลบข้อมูลหรือตั้งค่าระบบยืนยันตัวตนของโรงพยาบาลให้ ดู [การเชื่อมต่อระบบ](/blood_audit/th/operators/integration-seams/)

ผลนี้ใช้สำหรับการทบทวนคุณภาพย้อนหลัง ระบบไม่ส่งการแจ้งเตือนไปยังผู้รักษา และการรันสำเร็จไม่ใช่หลักฐานยืนยันความถูกต้องทางคลินิก

## ข้อจำกัดของเส้นทางเกล็ดเลือด

ค่า `PLATELET_LLM_ENABLED` ใน repository เป็น false หากมีคำสั่งเกล็ดเลือดที่ต้องส่งเข้าเส้นทางทบทวนซึ่งยังปิดอยู่ แอปจะปฏิเสธงานที่ยังบันทึกไม่ครบและไม่บันทึกว่ารอบนั้นเสร็จแล้ว ตรวจขอบเขตที่อนุมัติก่อนเลือกกลุ่มข้อมูลเกล็ดเลือด
