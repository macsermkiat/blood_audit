เก็บรายงานในช่องทางทบทวนที่อนุมัติ รายงานเชื่อมข้อมูลคำสั่งทางคลินิกกับแพทย์และแผนก แม้รหัสผู้ป่วยจะเป็นรหัสแทน

รายงานรายเดือนใช้เฉพาะแถวเม็ดเลือดแดง โดยตัดแถวเกล็ดเลือดออกและปฏิเสธรอบที่มีแต่เกล็ดเลือด ใช้คิวทบทวนสำหรับกรณีเกล็ดเลือดที่บันทึกแล้วและต้องตัดสินผล

## เลือกรอบที่บันทึกผลแล้ว

กำหนดพื้นที่ข้อมูลและไฟล์ระบุแพทย์ให้ตรงกับรอบ `DCT.csv` เป็นทะเบียนเพิ่มเติมที่แยกจากชุดข้อมูลมาตรฐาน

```sh
export BBA_DATA_DIR=/srv/bba/data
export BBA_BDVST_CSV=/srv/bba/export/BDVST.csv
export BBA_DCT_CSV=/srv/bba/export/DCT.csv
uv run bba report --run-id RUN_ID --format html
```

แทน `RUN_ID` ด้วยรอบที่ต้องการ คำสั่งอ่านแถวที่บันทึกแล้วและแสดงพาธไฟล์ หาก policy หรือ redactor version ที่ใช้ขัดกัน หรือมีคำสั่งจากหลายเดือนตามเวลาท้องถิ่น คำสั่งจะปฏิเสธรายงาน

## เลือกรูปแบบ

```sh
uv run bba report --run-id RUN_ID --format json
uv run bba report --run-id RUN_ID --format pdf
```

| รูปแบบ | ไฟล์ใต้ `$BBA_DATA_DIR/reports/RUN_ID/` |
| --- | --- |
| `html` | `report.html` ที่ escape ข้อมูลแถวแล้วและมี provenance |
| `json` | `report.json` ที่มีข้อมูลรายงานและ provenance รายแถว |
| `pdf` | PDF รายเดือน CSV สำหรับคณะกรรมการ และ CSV รายแพทย์ |

PDF generator เขียน `physician_own_view_<physician_id>.csv` ให้แพทย์แต่ละคนที่เลือกในข้อมูลรายงาน ไฟล์หนึ่งมีแถวสรุปของแพทย์คนนั้น ตรวจผู้รับและช่องทางก่อนแจกจ่าย

## ตรวจที่มาของแพทย์และผลการประเมิน

ระบบเชื่อม `REQNO` ไปยัง `BDVST.DCTREQ` แล้วค้น `DCT.csv` แผนกของแพทย์ใช้เป็นกลุ่ม ward ในรายงาน ไม่ใช่ข้อมูลหอผู้ป่วยที่วัดจากการนอนโรงพยาบาลแยกต่างหาก หากขาดตัวแปรระบุไฟล์ คำสั่งจะหยุด

รายงานเก็บ provenance รายแถวเมื่อมีทั้งผลจากกฎและโมเดล จึงไม่ควรตีความว่าทุกรายการผ่านโมเดลแล้ว รหัส policy โมเดล redactor prompt และหลักฐานใช้ตรวจย้อนกลับ
