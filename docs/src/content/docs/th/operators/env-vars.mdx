ตัวแปรที่ต้องใช้ขึ้นอยู่กับคำสั่งและ transport โหมด local ต้องมี `BBA_DATA_DIR` ส่วนการส่งข้อมูลให้โมเดลและหน้าทบทวนต้องตั้งค่าเพิ่ม

<EnvVarChecklist />

## Local audit

`BBA_DATA_DIR` ต้องเป็นพาธแบบ absolute ที่เขียนได้และใช้เก็บข้อมูลถาวร มี run state source snapshot `identity.key` audit rows calls รายงาน และผลวิเคราะห์ เก็บไว้นอก repository ในพื้นที่ที่จำกัดสิทธิ์

`BBA_APPLICATION_CONFIG` ระบุพาธไฟล์ JSON ที่ตรวจด้วย `bba.application.config.ApplicationConfig` หากมี field ที่ไม่รู้จัก ระบบจะปฏิเสธ ค่าเริ่มต้นคือ `transport: "local"` และ `policy_version: "repository-policy"`

## Model review

ไฟล์ตั้งค่าสำหรับ cassette แบบออฟไลน์มีรูปแบบดังนี้

```json
{
  "policy_version": "your-approved-policy-version",
  "transport": "cassette",
  "cassette": "/srv/bba/cassettes/approved-synthetic.json"
}
```

กำหนด `BBA_APPLICATION_CONFIG` ให้ชี้ไปยังไฟล์นี้ หากใช้ live ให้ตั้ง `transport: "live"` ตัด `cassette` ออก และตั้ง `allow_live_api` เป็น `true` ติดตั้ง [dependency สำหรับ live](/blood_audit/th/operators/install/#ติดตั้ง-dependency-สำหรับ-live) แล้วส่ง `ANTHROPIC_API_KEY` ผ่านระบบจัดเก็บ secret ของ deployment การเรียก live อาจมีค่าใช้จ่าย

ทั้งสองโหมดต้องใช้ข้อมูลอนุมัติดังนี้

| ตัวแปร | เนื้อหาที่ต้องมี |
| --- | --- |
| `BBA_PRIVACY_POLICY` | JSON ที่มี `key_id`, `public_key_file` และ `approved_redactor` โดย redactor ระบุ `version`, SHA-256 `model_sha` ที่ไม่เป็นศูนย์ และ `gazetteer_version` |
| `BBA_PRIVACY_ARTIFACTS` | JSON object ที่ใช้ audit ID เป็น key แต่ละค่าคือ `PrivacyArtifact` ที่มี `evidence_chunks` ซึ่งลบข้อมูลแล้วและ `attestation` ที่ลงลายมือชื่อ |
| `BBA_DB_URL` | Postgres สำหรับ checkpoint ที่ทำ migration และกำหนดสิทธิ์แล้ว ใช้ `postgresql://user@host/database` |

ไฟล์ public key เก็บ Ed25519 verification key ขนาด 32 ไบต์ บริการลบข้อมูลในเครื่องที่ได้รับอนุมัติเตรียมหลักฐานด้วย `RedactionAuthority.prepare` บริการนั้นถือ private signing key โมเดลที่อนุมัติ และ k-anonymity gate เก็บ private key แยกจากแอปตรวจเลือด

attestation ผูกกับ prompt audit ID run ID รุ่น redactor และผลตรวจความเป็นส่วนตัวที่ผ่านแล้ว ต้องเตรียมด้วยชุดข้อมูล รุ่น package และไฟล์ตั้งค่าเดียวกับที่ใช้รัน หากข้อมูลอนุมัติหายไปหรือไม่ผ่าน กรณีนั้นจะอยู่ให้คนทบทวนในเครื่อง การยืนยันจากผู้เรียกหรือ digest เพียงอย่างเดียวไม่อนุญาตให้ส่งข้อมูล

ค่า `enable_missing_hb_positive_evidence` และ `enable_missing_platelet_defer` เริ่มต้นเป็น `false` เปิดใช้เฉพาะเมื่ออยู่ในนโยบายที่อนุมัติ

checkpoint store ใช้ DSN แบบ `postgresql://` ผ่าน psycopg ส่วน review adapter แปลง DSN ให้ SQLAlchemy ภายใน จึงไม่ใช้ `postgresql+psycopg://` กับตัวแปรร่วมนี้

## ข้อมูลแพทย์สำหรับรายงานและหน้าทบทวน

`BBA_BDVST_CSV` ชี้ไปยัง BDVST ที่ตรงกับรอบและมี `REQNO` กับ `DCTREQ` ส่วน `BBA_DCT_CSV` ชี้ทะเบียนแพทย์ ทั้ง `bba report` และ `bba serve-dashboard` ต้องใช้สองตัวนี้ `DCTREQ` ใช้ระบุแพทย์ ส่วนแผนกของแพทย์ใช้จัดกลุ่ม ward ในรายงาน

## การยืนยันตัวตนหน้าทบทวน

`BBA_DASHBOARD_AUTH_SECRET` ต้องยาวอย่างน้อย 32 ไบต์ UTF-8 identity adapter และ dashboard ใช้ secret เดียวกันเพื่อลงลายมือชื่อและตรวจ session ส่วน `BBA_DASHBOARD_PUBLIC_ORIGIN` ต้องเป็น HTTPS origin ที่ผู้ใช้เข้าจากภายนอก

CLI ฟังที่ loopback หลัง HTTPS proxy และไม่ได้ออกตัวตน reviewer ให้ ดู [เปิดหน้าทบทวนที่ยืนยันตัวตนแล้ว](/blood_audit/th/operators/integration-seams/#serve-authenticated-review)

## ตรวจว่าตั้งค่าแล้วโดยไม่แสดงค่า

คำสั่งนี้แสดงเฉพาะชื่อตัวแปรกับสถานะ รวมถึงตัวแปรที่อาจมีรหัสผ่านหรือ token

```sh
uv run python - <<'PYTHON'
import os
names = (
    "BBA_DATA_DIR", "BBA_APPLICATION_CONFIG", "BBA_PRIVACY_POLICY",
    "BBA_PRIVACY_ARTIFACTS", "BBA_DB_URL", "ANTHROPIC_API_KEY",
    "BBA_BDVST_CSV", "BBA_DCT_CSV", "BBA_DASHBOARD_AUTH_SECRET",
    "BBA_DASHBOARD_PUBLIC_ORIGIN",
)
for name in names:
    print(f"{name}: {'set' if os.environ.get(name) else 'unset'}")
PYTHON
```

โหมด local ไม่ต้องตั้งตัวแปรเสริมทุกตัว การมีค่าอยู่ไม่ได้ยืนยันว่าตั้งค่าถูกต้อง อย่าใส่ credentials ใน transcript ภาพหน้าจอ หรือ issue
