`bba.application.audit_bundle` ประกอบข้อมูลให้ `bba.audit_pipeline.run_pipeline` แผนภาพแสดงขั้นตอนหลักของ RBC ส่วนเกล็ดเลือดใช้ตัวค้นผลแล็บ ตัวจำแนก และกฎตรวจคำตอบของตนเอง

## เตรียมหลักฐานในเครื่อง

1. เก็บ CSV มาตรฐานเป็น snapshot ที่จำกัดสิทธิ์ ตรวจ hash, schema, code version และการตั้งค่าก่อนจำแนก
2. ตรวจและปรับข้อมูลด้วย `bba.ingest`
3. เลือกคำสั่งที่เข้าเกณฑ์ด้วย `bba.audit_orders` ผู้ส่งออกข้อมูลต้องคัดกลุ่มผู้ใหญ่ไว้ก่อน เพราะ export มาตรฐานไม่มีคอลัมน์อายุ
4. ใช้ผลแล็บตามชนิดเลือด สัญญาณชีพ และตัวตรวจ cohort เพื่อประกอบบริบทก่อนสั่ง เวลาจ่ายเลือดใช้เป็นจุดอ้างอิงหลักฐาน ไม่ใช่หลักฐานว่าให้เลือดแล้ว
5. เพิ่มข้อมูลสถานะเลือดรายยูนิต วัตถุประสงค์ที่ระบุ และการจองตาม MSBOS เท่าที่มี

## ใช้กฎ deterministic

pipeline เรียกตัวจำแนก RBC หรือเกล็ดเลือดกับแต่ละบริบท และบันทึกผลที่กฎตัดสินจบได้โดยไม่ส่งโมเดล คำสั่งเกล็ดเลือดร่วมในช่วง MTP ที่ถูกระงับไม่สร้างผลตรวจแยก

ผล RBC ที่เป็น `NEEDS_REVIEW` หรือ `POTENTIALLY_INAPPROPRIATE` จะเข้าสู่การตรวจสิทธิ์ส่งข้อมูล ส่วนเกล็ดเลือดต้องเปิด `PLATELET_LLM_ENABLED` เพิ่มด้วย ดู [กฎ Hb](/blood_audit/th/developers/three-tier-hb/) และ [การตรวจเกล็ดเลือด](/blood_audit/th/developers/platelet-auditor/)

## อนุมัติและส่งคำขอโมเดล

`bba.evidence_bundle_builder` รวมหลักฐานในเครื่อง ผู้รับรองที่อนุมัติปกปิดข้อมูลและลงลายเซ็นให้ prompt, audit ID และ run ID ที่ตรงกัน แอปพลิเคชันตรวจคำรับรองด้วย public Ed25519 key ดู [De-identification](/blood_audit/th/developers/deid/)

ตัวสร้าง prompt จัดรูปหลักฐานที่อนุมัติแล้ว ก่อนส่ง ระบบเก็บเนื้อหาคำขอและบริบทสำหรับกู้คืนใน manifest ที่แก้ทับไม่ได้ งานโมเดลใช้ checkpoint ใน Postgres transport สำหรับบริการจริงปิดการ retry อัตโนมัติของ SDK หากไม่ทราบผลการส่ง ต้องตรวจสอบก่อนส่งคำขอใหม่

ในโหมด local หรือเมื่อการอนุมัติไม่ผ่าน แถว RBC ที่ต้องใช้โมเดลจะบันทึกเป็น `NEEDS_REVIEW` พร้อม `privacy_admission_failed` โดยไม่ส่งบันทึกดิบเข้า transport หรือเก็บเป็นคำขอโมเดล

## ตรวจคำตอบและบันทึก

ระบบตรวจรูปแบบคำตอบ ตรวจข้อความอ้างอิงกับหลักฐานที่ปกปิดแล้ว และใช้กฎของส่วนประกอบเลือดนั้น ระบบเก็บความพยายามแต่ละครั้งตามลำดับ และเลือกครั้งล่าสุดที่ผ่านการตรวจ หากไม่มีครั้งใดผ่าน ให้ `NEEDS_REVIEW` พร้อม `hallucination_suspect`

`bba.audit_store` เขียนรายการเรียกก่อน เขียนผลตรวจตามมา แล้วเขียน commit marker เป็นลำดับสุดท้าย ผู้อ่านเห็นเฉพาะผลที่ commit แล้ว แอปพลิเคชันเขียนเครื่องหมายจบงานเมื่อบันทึกงานที่เข้าเกณฑ์และไม่ถูกระงับครบแล้ว จำนวนแถว ingest ไม่ใช่จำนวนผลตรวจ

## กู้คืน batch ที่ขาดช่วง

batch store เก็บสถานะ `pending`, `submitted`, `partial`, `complete` และ `failed` ฟังก์ชัน `resume_on_startup` ตรวจ code version, บริบท, นโยบาย และคำขอเดิมก่อนสร้างผลคืน

batch ที่เป็น submitted หรือ partial อาจกู้จากรายการเรียกที่บันทึกแล้ว หรือดึงผลจาก remote batch ID เดิม คำตอบใน cache ต้องผ่าน verifier จริงอีกครั้ง หาก manifest หายหรือเปลี่ยนจะกู้ต่อไม่ได้ ส่วน pending ที่ไม่แน่ใจว่าส่งไปแล้วหรือไม่จะเป็น failed และต้องให้ผู้ดูแลตรวจสอบ จึงไม่ควรรับประกันว่าทุกงานที่ขาดช่วงจะจบได้โดยไม่ต้องดำเนินการเพิ่มเติม
