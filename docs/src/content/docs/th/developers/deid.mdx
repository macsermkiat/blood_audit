`bba.deid_redactor` ปกปิดข้อมูลในบันทึกทางคลินิกก่อนนำไปสร้างคำขอถึงโมเดล แอปพลิเคชันรับเฉพาะหลักฐานที่ผู้รับรองที่เชื่อถือได้อนุมัติแล้ว การเปลี่ยนเลขประจำตัวหรือคำนวณค่าแฮชอย่างเดียวไม่ถือเป็นการอนุมัติให้ส่งข้อมูล

## ขอบเขตของการปกปิดข้อมูล

`redact_bundle` รับ `RedactionRequest`, `RedactorBackend` และ `KAnonymityGate` ตัวห่อหุ้มแทนชื่อด้วยบทบาท เช่น `[PATIENT]`, `[ATTENDING]` และ `[NURSE]` แปลงช่วงวันที่ที่รองรับเป็นจำนวนวันเทียบกับวันรับไว้รักษา และจำกัดอายุในข้อมูลเชิงโครงสร้างไว้ที่ 89 ปี จากนั้นตรวจว่าการแทนข้อความทำให้ความหมายเสียไปหรือไม่

การตรวจ k-anonymity ต้องได้กลุ่มอย่างน้อยห้ารายจากชุดข้อมูล ward, ICD-3char, age band, sex และ admission month หากการตรวจความเป็นส่วนตัวไม่ผ่านหรือข้อความสูญเสียความหมาย ต้องส่งให้ทบทวนภายใน

ผู้ดูแลการติดตั้งต้องจัดหา backend และไฟล์โมเดลที่อนุมัติเอง repository นี้ไม่ได้ให้บริการปกปิดข้อมูลที่พร้อมใช้และผ่านการรับรองทางคลินิกแล้ว ห้ามใช้ backend ที่ปล่อยข้อความผ่านโดยไม่แก้ไขกับข้อมูลโรงพยาบาล

## การอนุมัติด้วยลายเซ็น

บริการในเครื่องที่เชื่อถือได้สร้าง `RedactionAuthority` ด้วย backend, ไฟล์โมเดล, privacy gate และ private Ed25519 signing key ของตนเอง `RedactionAuthority.prepare` ส่งออก `PrivacyArtifact` ซึ่งมีหลักฐานที่ปกปิดแล้วและคำรับรอง

แอปพลิเคชันได้รับไฟล์หลักฐานและ public verification key เท่านั้น ห้ามให้ private signing key แก่แอปพลิเคชัน `PrivacyAdmissionPolicy.verify` ตรวจลายเซ็นและผูกการอนุมัติกับ:

- เนื้อหา prompt และ task mode ที่ตรงกันทุกส่วน
- audit ID และ run ID
- รุ่น redactor, model SHA-256 ที่ไม่ใช่ศูนย์ และรุ่น gazetteer ที่อนุมัติ
- ผลตรวจ k-anonymity และการรักษาความหมายที่ผ่านแล้ว

หลักฐานต้องตรงกับบันทึกที่ปกปิดแล้วตามลำดับ และ evidence ID ต้องไม่ซ้ำ ผู้รับรองไม่ยอมรับ few-shot examples ที่ยังไม่ได้อนุมัติ ผลตรวจ prompt หรือความเป็นส่วนตัวอาจกำหนดให้ทบทวนภายในต่อไป

ตั้ง `BBA_PRIVACY_POLICY` ให้ชี้ไปยัง JSON ของนโยบายความเชื่อถือ และตั้ง `BBA_PRIVACY_ARTIFACTS` ให้ชี้ไปยังแผนที่หลักฐานที่ใช้ audit ID เป็นคีย์ ดูการตั้งค่าแอปพลิเคชันใน [ตัวแปรสภาพแวดล้อม](/blood_audit/th/operators/env-vars/)

ถ้าการอนุมัติไม่ผ่าน แถวที่ต้องใช้โมเดลจะเป็น `NEEDS_REVIEW` พร้อมเหตุผล `privacy_admission_failed` โดยไม่ส่งบันทึกดิบ ผลที่บันทึกเสร็จแล้วแก้ทับไม่ได้ หากต้องประเมินใหม่หลังได้รับอนุมัติ ให้ใช้รุ่นนโยบายที่อนุมัติใหม่และ run identity ใหม่

## บันทึกข้อผิดพลาด

CLI เรียก `bba.cli.phi_scrubber.install_excepthook` ก่อนเริ่มคำสั่งย่อย การ import `bba.deid_redactor` ไม่ได้ติดตั้ง hook ให้ทั้ง process

hook เก็บชนิดข้อผิดพลาดและตำแหน่งในโค้ด แต่ไม่แสดงข้อความ exception หรือค่าตัวแปรในเครื่อง เพราะข้อมูลเหล่านี้อาจมีข้อความผู้ป่วยหรือรหัสลับโดยไม่มีรูปแบบให้ตรวจจับได้แน่นอน ค่าตัวแปรจะแสดงเพียงชนิดและความยาว การป้องกันนี้ไม่ได้ครอบคลุมการเขียน log ตามอำเภอใจ จึงต้องไม่ใส่ bundle ดิบหรือข้อมูลรับรองใน log

## ข้อมูลสำหรับพัฒนา

ใช้บันทึกและเลขประจำตัวที่สร้างขึ้นทั้งหมดใน fixture และ cassette ใช้ `bba.deid_redactor.PHI_REGEXES` เมื่อต้องตรวจข้อความทดสอบที่มีรูปแบบคล้าย PHI แทนการคัดลอก regex ไปสร้างอีกชุด

ข้อมูลส่งออกทางคลินิกยังเป็นข้อมูลอ่อนไหวหลังเปลี่ยนเลขประจำตัว bundle ที่มีข้อมูลจริงผสมอยู่ รวมถึงข้อมูลเข้ารหัสหรือชุดที่เรียกว่า "mock-AN" ไม่ใช่ fixture สังเคราะห์ที่ได้รับอนุมัติ ห้ามนำ export ดิบ ข้อความผู้ป่วย หรือ bundle ทางคลินิกที่เข้ารหัสเข้า Git การเปลี่ยน AN ไม่ได้ยืนยันว่าข้อความส่วนอื่นไม่มีข้อมูลระบุตัวตน

โค้ดหลักอยู่ใน `src/bba/deid_redactor/redactor.py`, `src/bba/deid_redactor/admission.py`, `src/bba/application/audit.py` และ `src/bba/cli/phi_scrubber.py`
