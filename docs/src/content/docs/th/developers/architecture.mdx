`bba audit` ตรวจ export มาตรฐานจาก HOSxP และเขียนผลตรวจจริง `bba.application` เชื่อม CLI เข้ากับการประกอบบริบท การตรวจสิทธิ์ส่งข้อมูล และ `bba.audit_pipeline.run_pipeline` โดยใช้กฎ deterministic ก่อนพิจารณาส่งคำขอถึงโมเดล

## ขอบเขตของ package

| Package | หน้าที่ |
| --- | --- |
| `bba.cli` | อ่านคำสั่งและการตั้งค่า จัดการเครื่องหมายจบงาน และติดตั้งการป้องกันข้อมูลใน exception log |
| `bba.application` | เก็บ snapshot ต้นฉบับ ประกอบบริบททางคลินิก ตั้งค่า transport และเชื่อมรายงาน การประเมิน การติดตาม และการทบทวน |
| `bba.ingest` | ตรวจและปรับข้อมูล CSV มาตรฐาน |
| `bba.audit_orders` | เลือกคำสั่งที่เข้าเกณฑ์ และแยกคำสั่ง RBC ออกจากเกล็ดเลือด |
| `bba.hb_lookup`, `bba.platelet_lookup` | เลือกผลแล็บและแนวโน้มก่อนเวลาสั่ง |
| `bba.vitals_extractor`, `bba.cohort_detector` | ดึงบริบททางคลินิกเชิงโครงสร้าง |
| `bba.deterministic_classifier`, `bba.platelet_classifier` | ใช้กฎของส่วนประกอบเลือดแต่ละชนิด |
| `bba.returns_ledger`, `bba.declared_use`, `bba.preop_reservation` | ตีความสถานะเลือดรายยูนิต วัตถุประสงค์ที่ระบุ และการจองตาม MSBOS |
| `bba.evidence_bundle_builder`, `bba.deid_redactor`, `bba.prompt_builder` | รวมหลักฐานและกำหนดให้ผ่านการปกปิดข้อมูลที่อนุมัติก่อนส่งโมเดล |
| `bba.llm_client`, `bba.quote_grounder`, `bba.platelet_guardrail` | ส่งคำขอ ตรวจข้อความอ้างอิง และใช้กฎตรวจคำตอบ |
| `bba.audit_pipeline` | จำแนก แบ่งชุด ส่ง ตรวจคำตอบ บันทึก และกู้คืน batch ที่ขาดช่วง |
| `bba.audit_store` | เก็บผลตรวจ การเรียกโมเดลตามลำดับ และ commit marker |
| `bba.dashboard`, `bba.review_actions` | ตรวจตัวตนและบันทึกผลทบทวนพร้อมตรวจ revision |
| `bba.report_generator`, `bba.attribution` | สร้างรายงานที่ระบุแพทย์และที่มาของผลแต่ละแถว |
| `bba.eval_harness`, `bba.monitoring` | เทียบผลกับป้ายกำกับที่ทบทวนแล้วและผลตรวจซ้ำที่บันทึกแล้ว |

`bba.component_map` มีตัวจำแนกชื่อผลิตภัณฑ์เป็นหกกลุ่มด้วย แต่ตัวสร้างคำสั่ง HOSxP ใช้รายการรหัสผลิตภัณฑ์สำหรับ RBC และเกล็ดเลือด ไม่ควรสมมติว่าผู้เรียกทุกตัวใช้ตัวจำแนกชื่อ

## ข้อมูลและเงื่อนไขการกู้คืน

แอปพลิเคชันเก็บไฟล์ CSV เป็น snapshot ก่อนประกอบบริบท และตรวจเทียบกับ source identity, schema, code version และการตั้งค่า การแก้ export ภายหลังจึงไม่เปลี่ยน snapshot ที่กำลังประมวลผล

ผลที่กฎตัดสินจบได้จะบันทึกโดยไม่เรียกโมเดล แถว RBC ที่เหลือต้องผ่านการอนุมัติข้อมูลด้วยลายเซ็น หากไม่มีการอนุมัติ ระบบบันทึกให้ทบทวนภายใน ส่วนเกล็ดเลือดมี flag เปิดเส้นทางโมเดลแยกต่างหาก ถ้า flag ทำให้งานที่เข้าเกณฑ์ยังไม่บันทึก แอปพลิเคชันจะล้มเหลวโดยไม่เขียนเครื่องหมายจบงาน

manifest ที่แก้ทับไม่ได้ผูกลำดับ audit ID, หลักฐาน, prompt, การตั้งค่าโมเดล และบริบทนโยบายเข้าด้วยกัน การกู้คืนปฏิเสธข้อมูลที่เปลี่ยนและเรียก verifier จริงก่อนสร้างผลใหม่ หากไม่แน่ใจว่าส่งคำขอไปแล้วหรือไม่ ต้องตรวจสอบกับผู้ให้บริการก่อนส่งซ้ำ

ผลที่จบแล้วใช้คีย์ `(audit_id, run_id, code_version)` การใช้ `--force` ข้ามทางลัดของ CLI และบันทึกเหตุผลการฝืนรัน แต่ไม่เขียนทับผลหรือ manifest ดู [Audit store](/blood_audit/th/developers/audit-store/)

## สิ่งที่การติดตั้งต้องจัดหา

การตรวจ deterministic ในเครื่องไม่ต้องมีข้อมูลรับรองโมเดลหรือ Postgres การรันโมเดลด้วย cassette หรือบริการจริงใช้ฐานข้อมูล Postgres ที่ผ่าน migration แล้ว ส่วน dashboard ต้องมี review store, ตัวเชื่อมระบบยืนยันตัวตนที่เชื่อถือได้ และ HTTPS reverse proxy

แอปพลิเคชันไม่ได้รวม backend ปกปิดข้อมูลที่โรงพยาบาลอนุมัติหรือบริการออกตัวตนผู้ใช้ ดู [การเชื่อมแอปพลิเคชัน](/blood_audit/th/operators/integration-seams/) และ [ขั้นตอนประมวลผล](/blood_audit/th/developers/pipeline-stages/)
