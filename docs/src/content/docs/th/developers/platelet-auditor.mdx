คำสั่งเกล็ดเลือดใช้ตัวค้นผลแล็บและตัวจำแนกแยกจาก RBC ผลตรวจมี `component="platelet"` รายงานและหน้าทบทวนเก็บชนิดส่วนประกอบเลือดไว้ เพื่อไม่ให้ผลเกล็ดเลือดปนในสถิติของ RBC

## การรับคำสั่งและค้นผลแล็บ

ตัวสร้างคำสั่ง HOSxP รับคำสั่งที่มีผลิตภัณฑ์ RBC เป็น `red_cell` หรือคำสั่งที่เป็นผลิตภัณฑ์เกล็ดเลือดทั้งหมดเป็น `platelet` ผลิตภัณฑ์ที่ไม่รองรับและคำสั่งผสมที่ไม่มี RBC ถูกตัดออก `bba.component_map` มีตัวจำแนกชื่อหกกลุ่มแยกต่างหาก แต่ไม่ใช่ตัวคัดคำสั่งขณะรันนี้

`bba.platelet_lookup` อ่าน hematology `LABEXM = "290078"` หน่วย ×10³/µL ไม่มี POCT สำรอง `parse_platelet_count` รับค่าที่มี comma และค่าขอบเขต เช่น `<2` ส่วนค่าที่หาย ไม่ใช่ตัวเลข ไม่เป็นจำนวนจำกัด หรืออยู่นอกช่วงให้ `None` โมเดล `PlateletObservation` เก็บเวลา UTC ที่มี timezone และ lab `item_no` สำหรับตัดสินเมื่อเวลาเท่ากัน

เกล็ดเลือดที่สั่งร่วมในช่วง MTP ถูกระงับเป็นหน่วยตรวจแยกตั้งแต่ต้น ยังคงใช้เป็นสัญญาณ MTP โดยไม่สร้างผลตรวจซ้ำอีกแถว

## กฎ deterministic

`classify_platelet` ตรวจตามลำดับ:

| เงื่อนไข | ผล | เหตุผล |
| --- | --- | --- |
| ไม่มีผลแล็บและปิดตัวเลือก defer | `INSUFFICIENT_EVIDENCE` | `plt_missing` |
| ไม่มีผลแล็บและเปิดตัวเลือก defer | `NEEDS_REVIEW` | `plt_missing_defer_llm` |
| ค่า ≥ 100 ×10³/µL | `POTENTIALLY_INAPPROPRIATE` | `plt_ge_100` |
| ค่า ≤ 10 ×10³/µL, สด, มีข้อบ่งชี้, ไม่มีรหัสกลุ่มยกเว้น และเปิด prophylaxis auto-clear | `APPROPRIATE` | `plt_lt_10_heme_prophylaxis` |
| มีค่ากรณีอื่น | `NEEDS_REVIEW` | `plt_defer_llm` |

เกณฑ์ prophylaxis รวมค่าเท่ากับ 10 ด้วย ชื่อเหตุผลเดิม `plt_lt_10_heme_prophylaxis` ไม่ได้เปลี่ยนเครื่องหมายเปรียบเทียบ ต้องมี freshness เป็น `fresh` หรือเก่าน้อยกว่า 24 ชั่วโมง

รหัสวินิจฉัยที่เข้าเกณฑ์มี prefix `C8`, `C9`, `D61.1`, `Z51.1`, `Z94.8` และ `T86.0` ส่วน `D46` ต้องมี `Z51.1` หรือหลักฐานยาเคมีบำบัดล่าสุดเพิ่มด้วย pipeline ของ library ไม่ส่งข้อมูลยาให้ gate นี้ ดังนั้นเส้นทาง D46 จึงต้องมี `Z51.1`

รหัสยกเว้นครอบคลุม ITP, TTP/TMA, HUS, HIT, aplastic anemia บางกลุ่ม, dengue และพิษงู รายการ normalized ที่แน่นอนอยู่ใน `src/bba/platelet_classifier/classifier.py` ถ้าพบรหัสยกเว้นจะไม่ผ่านกฎ prophylaxis เชิงโครงสร้างนี้ และต้องส่งต่อ ค่าเกล็ดเลือดต่ำอย่างเดียวไม่พอ

`PLATELET_PROPHYLAXIS_AUTOCLEAR_ENABLED` เปิดเป็นค่าปกติของ pipeline ตัวจำแนกรับการเปิดผ่าน `PlateletClassifierInputs` จึงยังเป็น pure function การปิดตัวเลือกนี้นำทาง auto-clear เพียงทางนี้ออก กฎ deterministic ไม่ให้ผล `INAPPROPRIATE`

## เส้นทางโมเดลและการจบงาน

`PLATELET_LLM_ENABLED` ปิดเป็นค่าปกติ ผลเกล็ดเลือดที่กฎตัดสินจบได้บันทึกโดยไม่ต้องใช้เส้นทางนี้ ส่วนที่เหลือต้องเปิดเส้นทางโมเดลและผ่านการอนุมัติข้อมูลก่อนส่ง

เมื่อปิดเส้นทาง แถวเกล็ดเลือดที่ยังตัดสินไม่ได้ไม่ถูก commit `audit_bundle` ตรวจพบ orphan ID และล้มเหลวโดยไม่เขียนเครื่องหมายจบงาน การ ingest ผ่านหรือมีผล RBC บางส่วนจึงไม่ได้แปลว่าการตรวจหลายชนิดเลือดจบครบแล้ว

เมื่อเปิด pipeline ส่งเกล็ดเลือดเป็น batch แยกหลัง RBC ถ้าไม่ผ่านการอนุมัติข้อมูล จะทบทวนในเครื่องแทนส่งบันทึกดิบ ผลเกล็ดเลือดที่ commit แล้วแต่ยังต้องทบทวนปรากฏในคิวร่วมกับผล RBC ที่ยังต้องทบทวน

## กฎตรวจคำตอบ

คำตอบเกล็ดเลือดระบุสัญญาณที่มีหลักฐานรองรับสำหรับเลือดออก หัตถการ การป้องกันในภาวะไขกระดูกล้มเหลว เลือดออกในกะโหลก และ aplastic anemia ระหว่างรักษา `platelet_overclear_suspect` เปลี่ยน model `APPROPRIATE` ที่ไม่มีสัญญาณรองรับเป็น `NEEDS_REVIEW` พร้อม `platelet_llm_overclear_suspect`

ข้อบ่งชี้ใน prompt ใช้ขอบเขต ≤10, ≤20, ≤50 และ ≤80 ×10³/µL แบบรวมค่าเท่ากับตามแต่ละข้อ ส่วนข้อยกเว้นเป้าหมายสูงด้านผ่าตัดหรือเลือดออกในกะโหลกยังใช้ `count < 100` อย่างเคร่งครัด เกณฑ์เฉพาะข้อเหล่านี้ไม่ได้ทำให้กฎ deterministic อนุมัติทุกคนที่ต่ำกว่าเกณฑ์

กฎเพิ่มเติมสองตัวปิดเป็นค่าปกติ:

- `PLATELET_TREND_GUARDRAIL_ENABLED` ต้องมี projection รองรับว่าจะลดถึง ≤10 ภายใน 24 ชั่วโมง เมื่อการคาดว่าจะลดเป็นสัญญาณบวกเพียงข้อเดียว `project_24h` คำนวณจากผลก่อนสั่งสองครั้งล่าสุด
- `PLATELET_SPECIALIST_TARGET_GUARDRAIL_ENABLED` อาจเปลี่ยน `INAPPROPRIATE` ให้ทบทวนเมื่อมีเป้าหมายจากผู้เชี่ยวชาญที่เข้าเงื่อนไข เป้าหมายนี้ไม่ใช่ข้อบ่งชี้บวกตามนโยบายด้วยตัวเอง

กฎร่วม `label_reasoning_conflict` ส่งคำตอบที่ป้ายกำกับขัดกับเหตุผลให้ทบทวนเช่นกัน การตรวจ quote ยังทำงานตามปกติ กฎเหล่านี้จำกัดคำตอบโมเดล แต่ไม่ได้ยืนยันความถูกต้องทางคลินิก

ดู `src/bba/platelet_classifier/`, `src/bba/platelet_guardrail/` และ `src/bba/audit_pipeline/replay.py` ส่วนข้อความ prompt อยู่ใน `src/bba/prompt_builder/`
